# OSSASTRA 功能模块审查与落实清单

版本：v1.0，2026-10-23。事实基准：VC02B产品 `a2fa0cd`，交接 `aa61015`。用途：今后按功能模块逐项审查架构、作决定、实施调整和接入正式内容。

**这是审查工作台，不是新功能授权书，也不是“最终架构已完成”的声明。** 现行用户硬规则仍以工程根 `OSSASTRA_RULES.md` 为准。本清单不替代它，不自动冻结候选接口、骨骼或数值。

## 1. 为什么按这个方式组织

以“角色能做什么、谁拥有这件事、怎样证明做对了”为单元，而不是每个脚本单开一项。一个功能可以跨多个脚本，同一个通用模块可以服务多种功能。迁移阶段编号不再充当功能名称。

每次选择一个主模块，连同它直接依赖的接口一起看；不要求把整张清单一次重写。**优先把操作→动作→动画→装备→技能→道具的大链条梳理通，再逐项深化内容和调优。** 涉及共有接口的决定，应标出会影响哪些编号。

分开维护两种状态：

- **实现现状**：候选已跑通／局部实现／仅定义／未迁入／阻塞。这里只表示当前证据，不表示最终质量。
- **审查进度**：待审 → 已理解现状 → 已定方案 → 调整完成 → 回归通过 → 用户验收。方案若决定保留现状，记录理由，也需完成相应验收。

下文方框用于**本轮正式梳理的验收**，初始全部未勾。不能因为旧测试通过就预先勾选。每轮结论关联代码提交和证据；有依赖改变时，已通过模块标记“需复验”。

## 3. 每项的功能与架构审查卡

源码入口均相对 `Assets/OSSASTRA/Scripts/`。入口是阅读导航，不要求最终继续保持同名文件或当前拆分粒度。

### M01 实体根、初始化与更新顺序

**功能范围**：组件装配、初始化依赖、Update/LateUpdate调度、暂停/失焦/禁用/销毁、每类实体生命周期。

**当前入口/所有者**：`Characters/Runtime/CharacterRoot`；`Enemies/Runtime/EnemyRoot`；NPC使用独立根。角色根Update调用StateArbitrator.ManagedUpdate后提交表现；LateUpdate消费同帧身体姿态并推进装备/临时物品。场景服务负责队伍/库存等跨实体职责。

**重点核查**：实际时序是否逐段可解释；子模块是否另开Update造成双更新；独立根能否复用Combat而不依赖玩家组件；初始化失败是否明确且不会半初始化运行。

- [ ] 列出初始化、Update、LateUpdate实际顺序及每步读写数据。
- [ ] 暂停/失焦/死亡/禁用后，各时钟、请求、投递和表现的行为有明确区分。
- [ ] 保存重开、禁启、模型重绑不重复注册，不产生第二写入者。

### M02 角色数据、能力接口与状态所有权

**功能范围**：角色配置、运行数据、跨模块查询、能力依赖与事件事实。

**当前入口/所有者**：`CharacterDefinitionSO`、`CharacterDataBus`、`CharacterContracts`及领域contracts；资源/装备/库存状态分别由对应领域所有者维护，DataBus不是所有状态的副本；Combat注册机拥有唯一BasicActionRuntime，AbilityRun/装备payload/InventoryLedger分别保留既有状态所有权。

**重点核查**：哪些字段是权威、快照或只读投影；哪些组件需注入接口而非互相GetComponent；接口按角色/战斗/库存领域放置是否清楚；避免把所有接口堆成无边界总文件。

- [ ] 每个可变状态标出唯一写入者、读者和销毁条件。
- [ ] SO不保存当前HP/CD/数量；两个角色共享定义时运行状态独立。
- [ ] 明确DataBus可写边界与接口依赖方向；无双份可独立写的真值。

### M03 输入、手势、控制权与UI捕获

**功能范围**：键鼠采样、Press/Hold/Tap/LongPress、双角色切控、玩家与伙伴让权、UI焦点与持键重武装。

**当前入口/所有者**：`CharacterInputHandler`、`CharacterControlCoordinator`、`CharacterIntentSelector`、Core `GestureRecognizer`；场景唯一Current，本体接收输入/候选帧；PlayerInputLayoutSO为配置源。AM03及定向修正已接通设备来源/手势凭据、同帧按下释放与UI不补攻，未测实体手柄手感。

**重点核查**：输入意图与接受成功分离；切控/失焦后的旧按键不得补发；背包开着可走、文本输入时不可走；点击UI不能穿透打击；同次手势不能被两个消费者重复提交。

- [ ] 方向持续按住时闪避/攻击可正常受理，切控后旧持键不会误放技能。
- [ ] 手势优先关系与消费点明确，同键换装备可改变手势/功能。
- [ ] 开包、编辑数量、关闭UI、失焦回来四条输入路径实测。

### M04 动作仲裁、状态、时间线与取消

**功能范围**：候选优先级、能否接受、身体/左右手通道占用、前摇/释放/恢复、预输入、打断和已离手效果。

**当前入口/所有者**：`StateArbitrator`登记五状态机；`CharacterCombatStateMachine`拥有唯一Runtime/连段；`CharacterActionCoordinator`与Core `ActionAdmissionLedger`保持事务受理；`AbilityRun`、`ActionDefinitionSO`保持能力/时间线。Root公开请求转发，仲裁器显式分阶段推进。Enter/Exit当前观察边沿；Movement/Combat子状态部分按真实事实推导，未复制所有旧子状态对象。

**重点核查**：仲裁器、状态机、执行器、动画各自负责什么；MoveReady/AttackReady/Finished是否独立；按执行ID取消能否只取消目标动作；不把所有互斥压成一个busy布尔值。

- [ ] 绘制一个动作从候选到结束/取消的状态图，标明费用提交点。
- [ ] 先后或同帧发起普攻/闪避/副手/技能/道具时，结果确定且无重复消费。
- [ ] 释放前取消、释放后取消、死亡、切控分别验证；已经离手效果不被错误退款或重发。

### M05 移动、朝向、瞄准与碰撞

**功能范围**：键盘移动、视觉翻转、鼠标攻击朝向、动作位移、受迫位移、墙体/坡面与落点。

**当前入口/所有者**：`CharacterMovement`、`CharacterOrientation`；Movement执行本体移动，能力提供运动请求；敌人拥有自己的Movement。

**重点核查**：视觉朝向、移动向量、攻击瞄准不要混成一个值；键盘左右可翻转，攻击时鼠标优先；3D世界碰撞与2D Spine表现分离；不同位移来源仲裁而非多脚本同时写Transform。

- [ ] 静止瞄准、左右跑、边跑边攻击、攻击后恢复移动表现一致。
- [ ] 冲刺/火箭/击退撞墙正确，不能绕过唯一移动执行端。
- [ ] 明确CharacterController形状、地面平面、模型PPU/比例与受击几何各自意义。

### M06 普攻、连段与主手动作组

**功能范围**：四段普攻、空挥续段、有限预输入、末段恢复、主手I/II动作组及不同动作几何。

**当前入口/所有者**：`CharacterMainAction`、`MainActionProfileSO`、`MainActionSequence/BasicChainState`；按本次接受冻结动作，原Runtime推进。

**重点核查**：是否命中与是否允许续段分别定义；默认rozeul四段和迁移原型动作组不混为同一套；换装/切控/受击是否清理正确的缓冲。

- [ ] 空挥与打怪都按已决定规则衔接，按住攻击不意外产生无限连段。
- [ ] 每段释放一次、命中集合/派生身份可追，末段回到可操作状态。
- [ ] 更换动作组只换定义，不修改Root或写死动画名字。

### M07 身体动画、语义映射与过渡

**功能范围**：移动/待机/普攻/闪避/技能/受击/死亡语义、片段路由、混合、循环、重播、逻辑解锁后的动画交接。

**当前入口/所有者**：身体实际view为`CharacterAnimationController`，配合`CharacterAnimationConfigManager`、`CharacterAnimationComposer`、`AnimationHandleSystem`；`ActionDefinitionSO.animationLogicId`经Router→Override/Mapping生成完整快照。根Inspector直接导航场景实际Map/Router/Rig并显示已执行只读信息。旧CharacterSpineView/CharacterAnimationProfile与animationKey仅历史兼容入口。

**重点核查**：对照旧VELGITA的映射/过渡思路，哪些成熟能力已覆盖、哪些需要补；完整招式片段可保留，不强制拆前中后摇；动画结束和动作允许移动不是同一事件；不能从名字猜背面或原生事件用途。

- [ ] 移动解锁并实际移动时，身体切到正确移动表现，不继续滑行播放完整攻击尾段。
- [ ] 接受快照、轨道/混合/循环/连续同片段重播身份明确。
- [ ] 列出本轮采用的rozeul语义→片段→原生/派生事件；坏映射有诊断，不静默回退。

### M08 闪避、无敌与防御

**功能范围**：方向闪避、无敌窗口、体力费用、方向格挡、持续持盾、盾攻击及各自运动限制。

**当前入口/所有者**：`CharacterDodge`、`DirectionalGuardAbilitySO`、`CombatDefense`；盾的具体行为来自装备绑定。`ShieldGuard`等旧路径仅兼容，需核查装配互斥。

**重点核查**：防御结果来自共享接触网关，不由盾动画决定；相同盾类别可绑定不同功能；长按成本、启动成本、取消成本不重复。

- [ ] 闪避按键与持续方向组合、无敌起止、资源不足拒绝可实测。
- [ ] 盾A按住防御、盾B按下攻击，不更改Root即可替换。
- [ ] 正背面攻击、破势、松开、死亡/切控导致的防御退出符合约定。

### M09 体力、生命、架势、硬直与回复

**功能范围**：HP/体力、资源预留、架势/破势、硬直、虚血/夺回、普通治疗与持续恢复。

**当前入口/所有者**：`CharacterStamina`；Combat的`CombatVitals/Posture/Recovery/Regeneration`与对应Core状态；中立HP网关是结算入口。

**重点核查**：资源归属和时钟；整次技能夺回预算与多段命中去重；恢复叠加/互斥；死亡之后不继续治疗成复活；HUD只读取事实。

- [ ] 每种资源有明确上限、增长/扣除入口、暂停与死亡政策。
- [ ] 拒绝动作不扣费，预留释放/回滚与实际消耗可对账。
- [ ] 多段夺回、缓回药/食品、共享Y并存时无双重恢复或错误覆盖。

### M10 装备实例、装卸与左右手能力

**功能范围**：手槽、装备资格、实际持有、换装/卸装、耐久/CD/弹仓/技能选择随原装备流转。

**当前入口/所有者**：`EquipmentDefinitionSO`、`EquipmentItemState/EquipmentAbilityState`、`CharacterEquipment`；B由InventoryLedger持有唯一位置与payload，角色只读当前手槽绑定。

**重点核查**：装备“类别”和“功能”分离；正式Root不写盾/炸弹特判；空手真实为空；旧枚举入口和旧兼容组件不可重新生成副本。

- [ ] 同一武器包→手→包→地面→手的ID/耐久/CD/弹仓/技能选择不重建。
- [ ] 主副手可按通道合法并行，主手技能不依赖另一只手恰好拿盾。
- [ ] 满包卸装/非法资格/战斗中换装等拒绝整笔发生，无半成功。

### M11 独立装备Spine、挂点与临时道具表现

**功能范围**：独立模型挂接、角色语义与装备片段联动、内部握持点、翻转/颜色/显隐/排序、使用物品临时显示。

- [ ] 两人同装备定义、两只手分别动画，实例/材质/回调不串。
- [ ] 位置/角度/缩放/镜像/握持点/显隐逐项验证，缺挂点明确拒绝。

**功能范围**：Q/R装配、固定E、装备输入绑定、执行器组合、CD/占用/来源、普通技能与实验根。

### M14 投递、命中、防御与效果结算

**功能范围**：扇区/射线/弹体/抛物/组合投递，目标筛选、LOS、连续碰撞、范围/多段去重、共享伤害入口。

**当前入口/所有者**：`CombatDeliveryQueue/CombatContactGateway/CombatMeleeHit`、Core `AttackRelease`；中立Combat不应依赖角色库存或玩家根。

**重点核查**：投递与收费解耦；父执行/释放序号/目标身份去重；RayLandingArc落点查询+弧线表现与逐帧Parabolic碰撞不能混称同一模型。

- [ ] 近战、直射、飞行、范围落地都经同一合法结算端，墙/同层/目标资格正确。
- [ ] 多次回调/穿透/持续区/同帧多段不多扣血或错误只打一段。
- [ ] 装备投掷和消耗物投掷复用投递，但费用分别来自各自真实来源。

### M15 效果来源、分支、符文与持续场效果

**功能范围**：来源启停/互斥/覆盖、接受快照、17分支/10符文、减速/眩晕/击退、冰区/冰柱等派生物。

**当前入口/所有者**：`EffectSourceDefinitionSO/EffectSourceSet`、`CombatStatusEffects/CombatIceWorld/CombatIceColumn`及各能力消费者。

**重点核查**：注册不等于被消费；active/dormant/superseded/unresolved可说明；撤回来源对已接受直接伤害和依赖持续持有的副作用采用不同政策。

- [ ] 17分支/10符文按A覆盖表逐项核对真实消费者，不只核数量。
- [ ] 每类状态/场效果标明计时者、来源、叠加/合并、撤回与死亡清理。
- [ ] 冰柱HP/碎裂/碎片、碰撞对临时穿透与恢复无第二套生命/移动权威。

### M16 物品定义、实例、容器与事务

**功能范围**：物品尺寸/品质/堆叠/重量/价格元数据，实例ID/数量/位置，团队/安全/后备/手槽/外部/地面容器。

**当前入口/所有者**：`ItemDefinitionSO`、Core `InventoryContracts/InventoryLedger`、`InventorySession`；Ledger唯一数量/位置，SO无运行数量。

**重点核查**：试算与提交、修订/访问代际、数量预留、交换/拆合/整理守恒；共享定义和共享实例是两件事；重量目前仅显示。

- [ ] 全局实例唯一位置，拆分仅普通堆产生新ID，装备payload不复制。
- [ ] 容量不足/坏修订/重复请求/过期权限整笔拒绝。
- [ ] 整理方案提交前重验，有限算法不承诺最优，也不复活已消费物品。

### M17 背包操作、箱子、地面与快捷引用

**功能范围**：选中详情、拖拽抓取偏移、拆合/Ctrl/卸装/整理、同图地面物、F拾取、热栏1–0引用。

**当前入口/所有者**：`InventoryView/InventoryPointerTarget/InventoryWorldView`、`InventoryInteraction`；UI发命令，不自己移动真物品。

**重点核查**：访问3米/同层/LOS；点击与拖动分界；无选中不显示详情；落在无效UI不是地面丢弃；箱/散落物/篝火不各自处理一次F。

- [ ] 三尺寸实际操作多格物品、数量输入、取消/重开；窗口不遮住必要操作。
- [ ] 鼠标落点丢弃、F拾回、地面拖入精确格、满包提示且物品保留。
- [ ] 1–0与优先为引用，清除引用不删物品；不偷偷新增快捷使用语义。

### M18 道具使用、持续恢复、投掷与共享Y瓶

**功能范围**：药/五食品、消耗投掷物、使用资格、接受预留/释放消费、临时显示；Y共享服务与篝火。

**当前入口/所有者**：`InventoryItemUse/InventoryUseContracts`、`RegenerationAbilitySO/CombatRegeneration`；`HealingBottleService/PartyConsumableInput/PrototypeCampfire`保持独立服务。

**重点核查**：普通消耗物与装备、共享Y三种来源不得混合；效果互斥/暂停/死亡；UI及伙伴均请求能力，不直接生成弹体或写HP。

- [ ] 使用前后移动来源、切控、死亡、取消、重复Release均不复制或重复消费。
- [ ] 五食品与药实际缓回；满HP/互斥拒绝不扣数量。
- [ ] Y全满不耗、只治合法活体；返场/开包不补瓶，篝火按已定服务规则补充。

### M19 伙伴跟随、自主战斗、持有与用物

**功能范围**：非实控跟随、交战目标/范围/退让、攻防请求、药/投掷物有限策略、玩家接管。

**当前入口/所有者**：`CharacterFollow/CompanionCombatBrain`、`CompanionFollowDirector`、`CompanionInventoryConsumer`；队伍给目标/资格，本体能力生成候选，原Root接受执行。

**重点核查**：哪些是角色通用能力、哪些是场景队伍协作；AI不能自己直接移动/扣血；后备真实持有，优先只影响意图；战斗状态不应被闲聊互动抢占。

- [ ] 两角色切控后对称地跟随/自主攻击；威胁变化/失目标可恢复行为。
- [ ] 跟随、战斗移动、使用物品候选的优先顺序与饥饿/卡住处理明确。
- [ ] 交付→设优先→真实用药/投弹→接管→收回全程守恒，不重复请求。

### M20 死亡、全灭、掉落、返场与会话

**功能范围**：单死、全灭事件、生命周期代际、掉落包、返场恢复、同场会话清理。

**重点核查**：同一全灭事件只一次；安全位排除；旧掉落包保留；已离手效果/旧请求的生命代际；明确同场会话与未来存档/跨图边界。

- [ ] 单死无全灭掉落，双死只一个本次包，安全位保持。
- [ ] 返场→拾回→原武器再用，ID/资源/技能配置一致；空手不能幽灵施放。
- [ ] 二次全灭不覆盖旧包；退出新会话清理政策明确，不声称已支持跨图保存。

### M21 特效、声音与玩法事实反馈

## 5. 防止模块各自正确、接起来失败的五条复验链

|闭环|关联模块|必须保持的事实|
|---|---|---|
|输入→普通攻击→移动恢复→身体/装备动画交接|M01–M07、M11、M21|单一动作时钟；解锁、位移和表现同步；无滑行后摇/重复释放|
|箱内武器→装手→配技能→施放→卸装拾回|M10–M14、M16–M17、M22|同一payload；费用/弹仓/CD/技能配置不重建；UI事实一致|
|道具→交给伙伴→优先→自主用物→玩家接管|M03–M04、M16、M18–M19|真实数量；策略只提候选；接管不重复付费或赠送|
|敌预警→受击/破势→单死→全灭→返场拾回|M08–M09、M14、M20、M23|共享网关；安全位保留；同次掉落去重；返场不克隆|
|更换身体/装备/音画定义→复演同一动作|M07、M11–M12、M21、M24|配置可替换；结算身份/次数不变；坏挂点前置报错|

只重跑本次改变可能影响的链和已知边界；不为勾清单反复跑无关旧实验。发现新缺口先登记，再决定是否属于当前审查范围。

## 6. 暂不混入本清单的外围业务

家园/居民生活、旅行/跨图、商人买卖、农田/环境照明、完整存档、正式成长经济、全敌库、剧情任务与地图工坊没有因VC02B完成而自动迁入。收藏品/魔素瓶/材料/钱币的定义或显示也不等于对应业务已实现。

这些功能后续获得明确计划时再新增稳定模块编号；不要把当前24模块的全部验收绑到外围系统全部完成。
