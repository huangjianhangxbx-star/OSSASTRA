# v1.2：体素配色与受光校准

本轮接续方案C和v1.1，目标是交付能直接比较、复用和保存的材质候选。没有把“明艳”继续简化成增加亮度，也不要求用户先给出色值。

**当前作者推荐为“清透推荐”**；“浓厚暖砂”作为可选材质方向保留。本文记录已实际查看的七张实机原图和作者操作约定，技术验收、发布回执由后续验证记录补齐；作者推荐不等于用户已认可。

## 在主场比较和保存

沿用当前45°主场，在既有“体素受光”窗口选择：

| 入口 | 内容 |
|---|---|
| 原C | 恢复本轮接手时保存的原材质引用与C响应，保留旧效果对照。 |
| 清透推荐 | 浅暖石材、深木与集中绿叶配色，配合克制的已有受光响应。 |
| 浓厚暖砂 | 石材更偏暖砂、赭色的可选方向；并非另一套渲染算法。 |

已有两条独立滑条继续可用。**保存完整Look候选**与**显式设为本对象集默认**分开：保存应包含材质色板、响应Profile、明确绑定列表及原引用快照，不能只保存两条滑条。预览、已存候选与已设默认应按窗口实际状态区分；首次交付保留旧启动状态，不批量替换全项目默认。

P0接手时编辑器已退出Play，读回的原C作者值为分面0.65、亮面0、背光0。附件截图中的亮面50%是一次未保存的试调记录，不被当作已批准默认。独立C0仍保留为技术复位，不替代本轮原C对照。

## 本轮配色与响应

下列数值是设计的**作者固有色输入**，不是从参考图亮面抽取的最终像素，也不是固定“顶面亮、侧面暗”的上色。

| 材质族 | 清透主色 RGB | 稳定同族变化 |
|---|---|---|
| 浅石 | 0.74 / 0.70 / 0.60 | 三个整砖变体，约±0.025。 |
| 深木 | 0.27 / 0.19 / 0.12 | 三个整木段变体，约±0.015。 |
| 绿叶 | 0.24 / 0.38 / 0.15 | 三个整树冠簇变体，约±0.015。 |

石材同时试过中性浅灰0.70/0.71/0.67与暖砂0.75/0.66/0.50；最终保留清透方向优先。浓厚暖砂的石材主色为0.68/0.61/0.47。变体按整块稳定分配，四格对照使用相同的Mesh、法线、Transform与材质槽分配，不每帧随机，也不按太阳方向决定固有色。

组合候选R1使用现有参数：分面强度0.45、亮面增强0.15、背光压暗0。四格R0为分面0.65、亮面0、背光0。其余响应保持：GI漫反射0.65、环境反射0.25、直接镜面1、高亮保护0、拐点4、上限8、合成诊断0；未借此改变全局太阳、环境底光、曝光或二维角色光感。

当前共27个登记绑定，其中15个旧石/木/叶绑定与4个新样本，共19个绑定按明确的“原材质→候选材质”映射切换。旧几何和原作者材质保持；球体、屋顶、中性见证及底板不进入该配色映射。旧台阶、墙帽与门梁的候选变化同时用于检查第二种几何的复用。

## 新体素构件怎样复用

1. 先按石、木、叶选择已有候选材质族，用正常作者色入口输入；沿用当前线性工作流，不额外叠加一次Gamma/Linear转换。
2. 每块石砖、木段或树冠簇使用一个稳定变体，同一块的各面保持同一固有色。台阶、挑檐、凹槽由真实几何与光照形成层次，不画固定阴影。
3. 明确登记Renderer、完整材质槽和原引用，在Look中建立原材质到候选材质的映射。不要把“是MeshRenderer”作为全场批量换材质的理由，也不要编辑共享原材质来试色。
4. 复用同一响应Profile，在真实主场转镜头、移动太阳、看暖灯与冷夜，再检查窗洞许可路径。新构件不应需要专属补灯或专属Shader条件。
5. 保存完整Look候选，退出Play、重开后读回材质与响应。确定适用对象后，再通过单独动作设为该绑定组默认。

## 实机作者复核

七张原图采用同一几何、45°机位、正午与全局条件。四格说明：

| 比较 | 实际观察 |
|---|---|
| M0R0→M0R1，仅响应 | 略有提亮，灰绿或水泥灰的材质身份基本未变。 |
| M0R0→M1R0，仅配色 | 改善最大；台阶、墙帽与中间面明确成为浅暖石材。 |
| M1R0→M1R1，组合 | 增加少量清亮感，过渡稍松；应归因为配色主导、响应微调。 |

清透候选中，石材亮面呈浅米色，侧面保留灰褐或灰青倾向，接缝可读；本组未见明显大面积纯白、油膜或荧光黄。叶块转为集中橄榄绿后更协调；深木保持深棕，但不受光侧仍接近黑，不能据此宣称所有暗部层次都已改善。

中性候选较冷灰；暖砂更黄、偏砂岩；浓厚暖砂与清透有可辨的色彩身份差别，适合作为可选方向，而非更高质量的通用答案。参考图中的窄挑檐、凹槽、柱础还提供了更密集的明暗节奏；当前样墙已有分层、后缩背板与帽石，近机位和第二几何的复用证据需另行核对。高色度草地仍很抢眼，本轮保留真实背景，不以继续增黄石材来争抢亮度。

因此，**在本组固定条件下，材质配色起点是已确认的主要差距**。仅凭这七张最终截图不能判定共享颜色转换或tonemapping存在缺陷，也不能反推出各灯的线性贡献占比。颜色链诊断中的确定事实、候选原因与未排除项应与本节视觉判断分开记录。

## 实际验收与边界

2026-11-07：完整Look会话17项、保存15项Native合同通过；其中“已设默认后再次保存”的两项先实际失败，再加入最小写保护后通过。现行默认Look及其响应不可被普通保存原位覆盖，须另选独立保存目标。主场完整候选保存、磁盘重开、显式默认接入后还原原启动状态均已验证。技术C0、原C_live、A/B继续保留。

实际Windows主场Player构建成功，0错误、43项既有构建警告，62.23秒；DX11短程运行退出码0、121个实际主相机帧、27绑定、六状态全通过，运行错误0，原两角色见证通过。候选重入复用材质身份，缓存有界，恢复后90个已预热私有材质；这不是GPU耗时测量。Player不代替Editor磁盘重开证据。最终仅补了面板提示及完整候选读取按钮，Editor编译核验；未为文本改动重复整套Player。

四格的27个Mesh实例ID完全一致；全部对照使用同一机位/几何/灯光/正午/全场Look。已有灰绿色大底板仍未登记C，保留为见证，不应期待亮面滑条改变它。已有15个石/木/叶绑定和4个新小样共19个对象切候选；其他绑定保留C_live，球、屋顶、底板及2D不纳入色板映射。

Native DX11输入探针确认当前BaseColor只解码一次；现有22原绑定没有顶点色、贴图或_BaseColor的MPB覆盖。实际WorldLook为曝光0、对比6、饱和5，URP内置后处理关闭；未发现足以修改颜色管线的证据。实际主灯诊断0/50读回与图像不同，滑条有效；不能据最终截图反推实际GI占比。共享Shader数学、全局灯和后处理均未改。

近机位檐口/后缩凹槽、原台阶第二几何、夜间、室内窗洞/遮蔽与两角色均已留本机见证。19秒连续转镜头/太阳演示149帧，CSV和胶片图确认发生运动并恢复；录制低于目标帧率，不代表游戏性能基准。主要可视限制仍是背光深木接近黑，以及现有背景色度很强；本轮没有用全局调整遮掩这些差距。
