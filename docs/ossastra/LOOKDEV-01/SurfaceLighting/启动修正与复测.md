# Player启动修正与复测边界

首次Release编译成功不等于运行通过。第一次实际Player返回首帧Forward/Outline不可用，第二次修正版详细记录为 `-1/-1`，Shader声明仍为0/2。两次前置失败均没有有效300帧性能结果，原始文件留档，不计为通过。

1. 独立最小复制复现同时发现 Material.HasProperty 会在 CopyPropertiesFromMaterial 后漏报 wrapper 新属性，而实际 Shader.FindPropertyIndex 仍正确。预检改查真实 Shader 声明，保留其余 Shader、Pass、关键词、描边状态 gate；瞬态复制合同由3失败转12/12通过，资产合同仍12/12。
2. 该修正没有消除 Player 初次接管失败。Root在同一个实际P1 Player稳定显示后，短暂通过候选面板再次点C，立即成功显示 RealToon/7物体17槽和正确C画面。这排除了Pass永久缺失/变体被剥离，证实首Update早于URP初始化的一次性尝试问题。
3. 自动初档现在等待明确同场游戏相机的首次 `endCameraRendering`，解除订阅，再于下一Update仅尝试一次。不会固定sleep、循环retry、绕开gate、新建相机或吞掉真正失败。空/其他相机不放行，引用变更取消，Release/禁用/销毁清订阅。8项生命周期合同通过；最终实际Player仍是必要证据。

因此“只做一次最终Release”的原计划发生了一次已证缺陷修复所必需的偏离：前两包不合格，最终包单独命名 `_Final`。视觉不再迭代。Shader未改，修正包复用缓存约20秒，不用重跑22分钟的初次Shader编译。不能宣称始终一次成功，也不能将初次失败报告改写为后续成功。

独立Player的GUI按钮不在Editor MCP范围内；该次仅使用computer-use观察明确Player窗口、展开面板、点击C、关闭自有Player；没有控制编辑器或安全提示。其余工程操作继续使用MCP。
