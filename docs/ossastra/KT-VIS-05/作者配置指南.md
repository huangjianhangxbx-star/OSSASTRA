## 1. 模型怎样拆

可以在一个 Blender/FBX 文件里制作整栋房屋，也可以作为一个 Prefab 拖入。进入 Unity 后，需要把显示职责拆成不同 Renderer：

```text
Building（一个建筑作者根）
├─ Structure：墙、柱、门框、压顶
│  ├─ 可按镜头隐藏的独立墙段
│  └─ 不参与隐藏的结构
├─ Roof：屋顶、遮盖天花板的独立 Renderer
└─ Contents：各房间地板、家具及已有业务物件
```

**同一个 Renderer 不能混合屋顶与墙/地板/内容。** 只给一个混合 Mesh 换材质槽不满足当前分组合同；应在建模或导入组织时分出子网格对象/独立 Renderer。屋顶对象不包含业务根，隐藏屋顶只处理显示，不能顺便禁用 Collider、灯、门或业务脚本。

墙顶封口归对应结构职责，不塞进 RoofGroup。需要隐藏的前墙段单独登记；长墙应按实际房间/门窗开口分段，不能用一个跨多个不相关房间的大 Renderer 代替必要墙段。

## 2. 四类作者登记

| 组件 | 必须登记什么 | 不应放入什么 |
|---|---|---|
| `BuildingVisibilityRoot` | 唯一 buildingId、真实内部体积并集、所有 Room/Portal/Roof/FrontWall、结构 Renderer | 不根据屋顶 Bounds 或名称猜建筑，不把室外整地图包进内部 |
| `RoomRegion` | 唯一 roomId、floorId、有效体积、房间地板和内容 Renderer | 不包含屋顶、跨房共用内容 Renderer、永久结构 |
| `RoofVisibilityGroup` | 唯一 roofGroupId、只含顶盖 Renderer；必要的屋顶标签射线排除 Collider | 不含墙顶、地板、台阶/承载面、墙/家具 Collider |
| `FrontWallGroup` | 唯一 wallId、primaryRoom、可选 secondaryRoom、从 primary 向外的局部法线、必要墙段 Renderer | 不登记整栋、不登记屋顶；成员必须已经属于本栋 structuralMembers |

同一房间内容 Renderer 只能属于一个 RoomRegion。跨房的大地面应登记到模块 `sharedSurfaces`，由片元所在空间裁剪，不把同 Renderer 重复加到各房。屋顶、结构、内容、sharedSurfaces 之间必须互斥；FrontWall.members 是本栋结构的显式子集，不是第四份混合内容。

已有敌人、工位和家具可以直接把它们的显示 Renderer 登记为房间成员，无须把业务根改造成 Room 子节点。保持原 HP、交互和保存组件所在根。

## 3. 建筑/房间体积

`occupancyVolumes` / `volumes` 是相对当前作者 Transform 的定向盒并集。盒的 Y 尺寸表示真实有效楼层高度；floorId 是稳定身份说明，不能代替高度几何。凹角房间可由少量盒组成并集，不应使用一个大盒包住墙外凹口。

默认进入水平收缩 `enterInset=.02`、退出水平余量 `exitMargin=.12`，单位为世界米；它们只影响 XZ 门槛滞回，不收缩贴地脚点的 Y 高度。不用把眼点塞进体积来修复错误脚点归属。

当前主控实际处于哪个 Room，哪个 Room 才是完整 Seed。建筑内部范围只授权本栋揭顶与当前 Seed 的必要前墙隐藏；不能把“曾到达”作为当前整房可见条件。

当前最终保存样板已Native重开确认：2栋建筑、4顶盖组、35前墙段、45实体视线阻挡，45°俯角；这些是样板配置数，不要求每栋新建筑照抄。

## 4. 配置真实门窗

在实际开口处设置 `ViewPortal`。组件 Transform 的本地 XY 平面贴合孔洞，**forward 从 inside 指向 outside**。

| 字段 | 配置方法 |
|---|---|
| `portalId` | 本模块内稳定且唯一，例如原样板 `portal-a-north` |
| `inside` | 本栋实际房间；不可为空 |
| `outside` | 邻房则引用本栋该 RoomRegion；室外留空。当前配置检查不接受把另一栋的 Room 直接塞进这里 |
| `apertureMesh` | 可读、位于本地 XY、与真实墙洞吻合的填充 Mesh；边界须为单环、3—7 边、共面凸形 |
| `open` | 门窗观察开合状态；与实体门/窗板位置同步，不是只改变文字 |
| `canSeeThrough` | 材质/开口是否允许视线通过；与能否走过去独立 |
| `canTraverse` | 作者通行信息；不自动改 Collider，也不授予观察权限 |
| `observerRange` | 人物观察点到孔洞多边形的最短三维距离上限；源码默认 6m |
| `maxSightDistance` | 越过孔洞后，沿目标侧法线延伸的有限距离；源码默认 8m，不是视线射线总长 |

凹形、多个分离孔、未填充的洞中洞不能靠取凸包补成“更大窗”。应由作者分成明确可支持的凸开口，分别登记。中心细分顶点可以存在，但边界必须来自实际三角形，不把未填充区域当窗口。

普通透明玻璃可设通视且不可通行，不应登记成不透明 sightBlocker。木板、实门、高柜等真正不透光物应进入 sightBlockers；门窗开着也仍会被这些实体截断。

同一个 Portal 自动按观察者所在侧生成相反方向视域，**不需要复制一扇反向 Portal**。仅改变相机位置不会让人物取得新的窗洞授权。反过来，同一逻辑视域在不同相机角度下能投影出的局部内容可能不同，这是正常的真实遮挡。

## 5. 前墙与共墙

`FrontWallGroup.primaryRoom` 是作者法线的基准侧，`localOutwardNormal` 用本组件的局部坐标表示由该侧指向墙外/另一侧。外墙的 secondaryRoom 留空；共墙填另一 RoomRegion。

当 primaryRoom 为当前 Seed，使用登记法线；当 secondaryRoom 为当前 Seed，求解器翻转法线。只有面向当前实际相机、确实属于该 Seed 一侧的必要前墙段可隐藏。`allowHide=false` 可让门框/支柱等显式保持。

**共墙不要求两边都成为完整房间才允许隐藏。** 它从当前 Seed 一侧按前墙处理；另一侧房间内容仍受 Seed/Portal 规则隔离。禁止为了露出当前 Seed，顺手把邻房整体设为可见。

前墙 Renderer 隐藏不等于删墙：原 Collider、攻击/交互规则、遮光结构继续保留。没有登记为前墙的结构、侧墙、背墙及与当前 Seed 无任一侧关系的墙不自动消失。

共墙两侧法线/权限已由Core20纯合同覆盖；同Lab实际八档相机、门板与原切控共12项通过。Core和实机回执各有范围，未宣称任意墙网格/每个共墙两侧全角组合均已人工审看。

## 6. 模块入口与调试面板

在原 `SceneVisibilityRoot` 的 `roomModule` 引用进入 `RoomVisibilityModule`；不要另加一个相机回调根。

| 配置 | 用途 |
|---|---|
| `effectEnabled` | 整个房间可见性模块开关，开发对照使用；关闭不暂停世界 |
| `revealRoofs` | 主控入有效建筑范围后统一揭本栋已登记顶盖；不授予邻房内容权限 |
| `positiveRenderingEnabled` | 当前合法视域合成；关闭仅用于旧图对照，不作为正式隔离策略 |
| `truthMode` | true 为纯色 Seed/Partial/Roof 诊断；本轮已验证的最终颜色与 WASD 运行使用 false，不把纯色真值误当最终材质 |
| `localObjectRevealEnabled` | 独立局部物件透视扩展，当前默认 false；不要为关它而关闭建筑模块 |
| `observerHeight` | 原 Current Transform 位置向世界上方的稳定偏移；源码默认 1.4m。不是相机位置，也不跟鼠标绕人物平移 |
| `sightBlockers` | 明确真实不透明 BoxCollider 列表，最多 64；禁用、inactive、Trigger 不作为实体遮挡 |
| `immediateResolveDistance` | 大位移触发立即重判归属的阈值，源码默认 3m；不负责移动角色 |

Inspector 的“检查建筑登记”会报告重复/空 ID、混合 Renderer、坏孔洞/距离、无效体积、墙段归属等，不自动修复。新增数组引用后显式检查；不要靠只看名字或改显示颜色绕过错误。

现有 LabPanel 可显示 observer/房间/Partial 数、前墙数和附近 Portal 两面/通视状态，提供合法合成、真值和局部透视开关；青框为开口投影，橙线为有限视域截面。它还通过原接口提供左右 45°转镜头、真实窗板/门板和室外/A/B 调试定位。

定位按钮使用原 Motor 的 Teleport，只是条件直达夹具。正式体验必须从原输入走门、靠窗、背对和离开。面板悬停会按 owner 捕获玩家/相机输入；测试自然输入时把指针移出面板。世界不因面板而暂停。

本轮已通过面板/原接口直达夹具、原InputAction步行和12项控制回执；面板定位与自然步行分别记录。完整帮助提示/实体硬件操作仍需作者实际体验，不是本轮技术实现待办。

## 7. 动态表现的归属

初始登记之后生成的掉落、装备或短命 FX，不能仅靠把 GameObject 放在房间根下来推断权限。原表现所有者可经 `RoomPresentationBinding.Attach` / `RoomPresentationRegistry.Register` 登记已有 Renderer、世界锚点和可选跟随锚点；Disable/Destroy 精确 Release，不接管业务生灭。

`ForcePartial` 只会收紧片元到合法视域；`RequireAnchorPermission` 可要求锚点先获许可。都不能让邻房变成 Seed，也不能通过改锚点把不可见敌人/UI 整体放出。具体新业务接线由对应原表现所有者维护，不由建筑模块创建第二份掉落或库存。

本轮已有6项纯登记合同及最终独立复跑的9项Native原工厂/表现检查：短命反馈、移动投射体锚、冰路、耐久条 Back/Fill 与过期路径，测试自有 5 Renderer/对象媒体/注册释放、原 Current/Vitals 不变。它们使用明确的显示年龄/位置/时间夹具，不能解释为所有实际技能发射、命中或 GPU/阴影已经验收。

## 8. 渲染候选与限制

本 Lab 使用自有可选 `RoomVisibilityRenderer.asset`，项目默认 Renderer 不改。Shader 显式引用应由本任务的 Native 配置入口接好；不要手工把整个项目的 Renderer 替换为这个候选。

静态成员按原源材质建立有界临时队列桶，用对应 overrideMaterial 绘制合法内容，范围结束归还自身写值；原材质资产不改。动态角色、Sprite、Spine和已登记表现完全不替换sharedMaterials；无光照路径绘制真实Renderer，动态Lit用原PerObjectData、Forward/ForwardOnly且排除Coverage/DepthHelper。静态桶最多256、动态Lit最多6源组/第7拒绝，保留渲染位16—31先查冲突，不改业务层/物理层。

最终8项桶合同、2个原装备Sprite经3对手工scope＋2真实帧引用保持、V4具体资源释放重接均通过。适配清单含URP opaque、薄地面、装饰、DepthPlane、Spine/Sprite等；本Lab颜色已实看，不等于全材质/透明/PMA矩阵通过。混合/未知家族、非Simple或带SpriteMask的SpriteRenderer当前保守省略/拒绝；不可把省略误认成正常揭顶。

当前最终世界源码对启用 postProcess 的相机拒绝继续，避免旧未受限深度进入景深等后处理。该限制不是已经完成所有后处理兼容的承诺。原URP Lit屋顶/灰墙方块、地面与角色的最终独立路线已有实际颜色证据；任意屋顶材质、全部光照与PMA矩阵属于未测试支持边界。

非合法空间纯黑是预期隔离；若合法 Seed/窗域也错误全黑，按“配置检查→当前 Seed/observer→Portal 与实体→真值颜色→最终源材质适配”顺序诊断。旧 overrideShader 的 Lit 全黑已被新材质桶路线修复，不应把那条旧失败当当前结果。不得用把黑幕调浅、关闭碰撞、删除屋顶或把原 `ZTest` 改 Always 来掩盖新错误。
