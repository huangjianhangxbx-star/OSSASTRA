## 建筑制作：两类必须分开

**永久结构**包括墙、墙厚、墙顶封口/压顶、柱、门框、地面及内部构筑。**顶盖**只包括遮挡内部观察的屋顶、天花盖和明确属于屋顶的附属视觉件。两类必须能独立登记Renderer；一体Mesh混合两类时，先制作明确分件或受控适配，不能运行时按朝上法线猜屋顶。

墙必须有实际厚度与顶面。揭顶不能露出无封口的墙壳，也不能把楼板、桌面、台阶或角色承载面当屋顶撤掉。门窗必须有真实几何孔洞；样板用完整Box墙段围孔，不靠透明整墙或假窗贴图。

一个顶盖Renderer只有一个Building归属，且只能放入该栋的一个顶组。它不能同时登记为永久结构、房间内容、共享地表或局部透视成员；Room没有独立隐藏本房屋顶的权限。不要让另一个脚本、动画或全局透明控制器同时改同一顶盖的显隐。

揭顶只改变本GameplayCamera的呈现。原Collider、业务根、灯光与世界时间继续运行。当前相机scope保留原投影：正常投影成员临时使用`ShadowsOnly`，原本不投影的成员不会新增阴影；相机结束后按所有权归还。不要手动永久改成`ShadowsOnly`，不要关闭建筑根、Collider或太阳来替代。

## 五类组件怎样登记

以下组件都在`Ossastra.SceneVisibility.Rooms`命名空间。先完成显式登记，再在模块Inspector点击“检查建筑登记”；检查只读，不会自动修复、生成ID或保存。

| 组件/字段 | 填写方式 |
|---|---|
| `BuildingVisibilityRoot.buildingId` | 本模块内唯一、非空的建筑ID；不由Tag、名称或门窗连接推断 |
| `occupancyVolumes` | 相对Building Transform的`RoomLocalBox[]`并集；`center/size`是局部中心/完整XYZ尺寸，Y就是实际有效高度 |
| `regions / roofGroups / portals` | 明确引用本栋全部房间/走廊、全部顶盖组及门窗 |
| `structuralMembers` | 本栋墙、墙顶、柱、门框等Renderer；保持自然遮挡 |
| `RoomRegion.roomId / floorId / volumes` | 区域ID全模块唯一；floorId是作者标签，高度资格仍以体积Y范围判断 |
| `RoomRegion.members` | 本区域地板、家具、敌人及工位等内容Renderer；可引用原业务根的显示子对象，不必移动业务层级 |
| `RoofVisibilityGroup.roofGroupId / members` | 顶组ID全模块唯一；登记该栋可隐藏顶盖，不按房间独立判断 |
| `RoofVisibilityGroup.labelRaycastExclusions` | 仅登记明确顶盖Collider，供揭顶后的世界标签可见性射线排除；禁止填墙/内容Collider。它不关闭碰撞，也不改变攻击LOS |
| `RoomVisibilityModule.buildings / sharedSurfaces` | 所有参与建筑；跨多个区域的原地表可放`sharedSurfaces`，按片元裁剪，不能与房间内容/顶盖重复 |
| `SceneVisibilityRoot.roomModule` | 指向同一Root组织的可选模块；继续复用原GameplayCamera、协调器和角色 |

建筑子树中存在未分类Renderer、内容跨区域重复、顶盖重复归属或结构允许局部透视时，配置应明确拒绝。外部原敌人、工位的真实Renderer同样须显式列入所属`members`。新动态显示对象不能只凭位置或命名假定已经自动登记。

`enterInset/exitMargin`只调整XZ进入/退出滞回，不收缩贴地脚点的Y资格。出生、传送、切控仍走真实空间重判，不依赖TriggerEnter；无需给CharacterController额外挂运动Rigidbody。

## 真实Portal与双黑幕

`ViewPortal.apertureMesh`必须是可读的本地XY平面孔洞网格，贴合实体墙洞；`transform.forward`从`inside`指向外侧。`outside=null`表示室外；填同栋邻区时只登记内部关系。`open`、`canSeeThrough`与`canTraverse`分别表示开合、观察许可、作者通行信息，组件不会据此修改碰撞或攻击。门/遮板移动时，作者适配必须同步真实几何与`open`。

- **ExteriorBlackout**遮蔽建筑外画面。只有已到达内区朝室外的合法开放孔洞可放行当前帧外景；实体墙、窗框和遮板仍参与真实深度。
- **InteriorUnexplored**隐藏本栋尚未到达区域的内容，保留可见结构。开着的内部门、B自己的外窗、伙伴所在位置及局部透视圆均不能提前解锁B内容。
- 只有原主控的稳定脚点实际进入区域才记为到达；ABC之间移动只增加本会话到达记录，不交换顶盖。离开整栋后恢复顶盖，D保持独立。
- 当前是**本运行会话探索**，未接入跨档永久探索；不是完整战争迷雾、视野锥或递归门户。切换主控沿原协调器权威，不另建Current。

模块可分别开关`exteriorBlackoutEnabled/interiorUnexploredEnabled`。`maskDebugMode`为0正常、1室外许可R、2室内已知G、3最终许可。世界血条/掉落名/交互提示须接入本相机的`RoomWorldPresentationGate`与专用世界标签材质；Overlay HUD不能成为未知信息旁路。标签过滤只限制表现，不授予拾取、交易或攻击资格。

## 局部物件、后端与限制

树冠/孤立石块的许可仍用`SceneOccluderGroup.occlusionPolicy`：`CharacterReveal=0`允许原柔边透视，`KeepNaturalOcclusion=1`保留自然遮挡。树干、结构墙和承载面应保持自然遮挡。仅关闭`allowWholeFade`不足以禁止局部开窗；不要交换旧枚举数值。房间/顶盖/黑幕不占原小物有限捕获槽。

本场自有Renderer为`Assets/OSSASTRA/GroundWorkshop/Samples/KT-VIS-04/Rendering/RoomVisibilityRenderer.asset`，包含`RoomMaskRendererFeature`；只由本场相机选用，不改项目默认Renderer或旧相机。新增材质必须先检查mask适配：当前包括符合不透明深度/混合合同的URP Lit/Simple Lit/Unlit、已有ThinTop/DecorationCutout/DepthPlane、已登记角色深度与Sprite/Spine路径。未知Shader、透明玻璃、折射和特殊PMA不能默认算支持；`RoomMaskStatistics.Error`非空或未支持材质计数非零时不能签渲染通过。

当前每栋建筑占用盒最多8个、该栋房间盒总数最多8个，相机显隐scope最多512成员；超限明确报错，不截断。完整多层楼宇、楼上承载地板兼作楼下顶盖、跨栋递归门户及任意透明材质尚需独立验证。

`ShadowsOnly`只证明保留相应ShadowCaster机制。实时定向光、室内局部光、真实窗孔及揭顶过渡须做正确封顶基线和真正撤销遮光的负对照；烘焙、探针、反射、SSAO与静态遮挡剔除分别记录，不能用阴影截图代签全部照明。没有GPU/Player/实体键鼠手柄证据时分别标“未执行”。
