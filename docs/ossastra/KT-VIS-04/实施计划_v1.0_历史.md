# 房间可见性实施计划

**Goal:** 在独立SC_RoomVisibilityLab交付主控入室揭顶、保留结构墙、室外黑幕/真实门窗与显式局部物件策略。
**Architecture:** SceneVisibilityRoot仍是唯一相机组织者；RoomVisibilityModule解析原Current脚点，提交房间/屋顶呈现快照；专用相机RendererFeature在透明物之后生成alpha/depth-correct许可mask，在后处理后/HUD前绘制黑幕。
**Tech Stack:** Tuanjie2022.3.62t16、URP14.2.0-t1、既有XZ角色/地表与有限捕获。
**Spec:** 用户授权KT-VIS-04 v1.0 ZIP的00—05全篇、2026-11-02最新Chat；本地保留外部研究/可见性修复/KT-VIS-04/plan-package。

## 全局边界

- 最新用户俯角35°优先于计划旧45°事实；35°交付、45°附加测试，源场保留。
- 结构墙、柱、框与承载面自然遮挡；伙伴不得扩大活动房间；顶组不可与局部透视组共管Renderer。
- 窗口使用当前帧真实世界、真实孔洞/深度；禁止假窗、切墙、角色置顶、关闭室外业务根。
- 源场dirty先Native另存可恢复副本，新场独立三Map/两Boundary/保存profile；每次Play前显式核对所有宿主与最终目录。
- 仅本机独立Renderer配置，默认Renderer/管线/物理/输入/库存/配方/音声不改；B模块验证，不扫全历史场。
- 运行代码不含任务号，准确中文头注释；原dirty/媒体/用户维护区保留；定向GitHub仅自有可发布文件。
