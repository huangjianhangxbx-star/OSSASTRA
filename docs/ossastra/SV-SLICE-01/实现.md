# SV-SLICE-01 横版最小闭环

用户选定的顺序为 Tut_01 → Tut_02 → 锁之塔休息房 → 铁笼升降机上层至下层 → 锁之塔战区 → Mossbone Mother。标题提供开始、退出和八个槽位。槽内的新建、继续、复制和删除通过会话及文件存储执行。复制按目标槽重写存档身份，删除在写锁内使旧写会话失效。

敌人由项目的 EnemyRoot 管理动作和共享命中。横版策略使用两名固定角色引用、阵营、XY 横距／高差和场景视线。招式受理时确定面向。受理后目标越界或绕背不会改变初始方向，碰撞和集中结算决定实际命中。普通敌人按场重建，休息接口可刷新所在场的已死普通敌人。Boss 另有遭遇状态：真实死亡回执记下稳定击杀事实，保存并关闭会话成功后才回标题。读入通关档可以从已保存检查点继续。

场景用同一 Commerce 快照保存物品、经济、一次性世界状态、最近休息锚点和 Boss 记录。关门等待最终写盘期间，周期存档不会继续增加修订。若只出现晚到修订，主线程重新冻结最新状态；真正的磁盘写入错误保留会话和明确的重试入口。保存椅和实体过门都复用保存屏障。

独立团结 Play 已验证 Bone Thumper 左向前摇、目标绕背时挥空、有效命中一次、高台目标未受伤，以及死亡和刷新。六图十门可通过真实碰撞触发往返；升降测试覆盖双人下行、途中切主控、单人上行和下层门禁。保存椅菜单的保存与出发已经走过真实写盘；D3D11 抓取六图的 Legacy、Silksong、Ace Fusion 共 18 张相机帧，并读回三模式的 ES 显示。标题 Play 复测覆盖新档、保存回标题、继续。集成验证使用主控近战结算触发 Boss 死亡，读取同一 ActionId 的回执，等待保存退标题并重新读取完成档。

锁之塔按所选参考重排了四个可玩房间。美术使用少量本机原作地景及自制场景布局。Gang 和 Mimic 的动作像素来自本机 4.1 Spine 素材的原位烘焙，使用项目动作和碰撞推进；丝之歌样本保留原帧、轴心和素材循环。两作实战的全部动作分支、奖励和阶段参数未逐项复刻。

横版正式入口是 `Assets/OSSASTRA/SideView/SC_SideViewTitle.unity`。它位于构建场景首位，并设为本机主工程的 Editor Play 启动场。标题选档后为六张地图传入同一存档会话。六张地图不再保存旧验证档的绝对路径和 Profile。未经过选档注入的场景拒绝访问存档；其他地图仍可按各自既有配置启动。

存档继续使用持久化目录 `SV-SLICE-01`、槽位 `slice-slot-01` 至 `slice-slot-08`，原有的 Map ID 和检查点 ID 保持有效。主工程用临时槽复测，覆盖物理门、升降机、保存椅按钮、Boss 死亡回执和完成档冷读。游戏场景和原素材在具备本机依赖的主工程中装配。 [R1 研究基线](README.md)
