## 2. 玩家的一次完整流程

1. 在新主场用现有攻击破坏资源点。石料与纤维仍走原世界物件生命/掉落链，地面物不会因打开合成面板直接变成余额。
2. 靠近掉落物，出现“交互 拾取”后按原交互键 **F / 手柄A** 收入团队背包。背包满时先整理空间；合成只读取团队背包可消费普通材料。
3. 从装备台前方靠近，出现装备台交互提示后按F打开。打开窗口的这次按下只开窗，不同时合成；同一帧多个确认来源最多提交一次。
4. 选配方，查看“可用 / 需要”、数量、产出和失败原因。默认1份，可用加减或数字框填写；样板每批上限8份。选择N份时整批成功或整批拒绝，不暗中减少份数。
5. 点击“合成”或再次按F提交当前有效预览。编辑数字时F不会成交；数字无效、材料变化或预览过期时须先重算。成功结果会显示实际成品、团队背包去向与实例ID。
6. 用窗口×、返回键或Esc退出。数字框处于编辑时第一次返回先退出编辑，下一次返回关闭窗口。窗口关闭后按 **Tab / Start** 打开原背包。
7. 在团队网格中按住鼠标左键拖动石刃，放到目标角色的**右手**槽；把石盾拖到该角色**左手**槽。两名角色各有自己的左/右手槽，要看准角色行。原背包的普通右键不是“一键装备”；它主要清除快捷引用。卸下已选装备可用详情里的“卸回背包”，也可拖回合法团队位置。 若换石盾提示容量不足，要为卸下的旧2×2副手保留连续格；本轮实际先将旧主手从team拖到safe合法格（slot0），再拖新石盾成功。不增加自动整理。
8. 关背包后使用现有角色输入：**鼠标左键 / RT 操作右手主手，鼠标右键 / LT 操作左手副手**。石刃复用原主手能力/表现，石盾复用原盾类副手；副手行为由装备定义决定，不把石盾当成新的独立攻击系统。
9. 保存后通过“保存并进入合成中转”进入中转场，再按本轮返回入口回主场；或退出Play后用同一隔离profile重新打开新主场。核对材料减少、装备所在位置、耐久/运行状态和同一实例ID。此步骤是用户复验操作，不表示本文已经代签重开通过。

合成界面、原背包和菜单**不暂停世界**。窗口捕获当前需要的输入，但敌人、角色已接受的动作与世界时钟继续。关闭面板不会自动装备成品，也不会补材料。不要在敌人攻击范围内把窗口当作暂停。

正常合成面板支持鼠标、uGUI导航/确认与返回。原背包仍沿原有拖放操作；本轮没有另造一套手柄装备网格，实体手柄完整体验需单独验收。按键以当前 `PlayerInputLayoutSO` 为准，本文是样板默认。

所有配方需要 `equipment` 工位能力。中间材料配方也在装备台目录中，类别标签只负责列表显示，不改变工位资格。

| 配方ID / 显示 | 每1份输入 | 每1份输出 | 成品配置 |
|---|---|---|---|
| `craft-binding-recipe` / 编扎纤维束 | `world-fibre` ×2 | `craft-binding` ×1，纤维束 · SAMPLE | 普通材料，1×1格，堆叠上限99 |
| `craft-blade-recipe` / 制作石刃 | `world-stone` ×2 + `craft-binding` ×1 | `craft-stone-blade` ×1，石刃 · SAMPLE | 右手装备，1×2格，每件独立实例，初始耐久100 |
| `craft-shield-recipe` / 制作石盾 | `world-stone` ×3 + `craft-binding` ×1 | `craft-stone-shield` ×1，石盾 · SAMPLE | 左手盾类装备，1×2格，每件独立实例，初始耐久100 |

从零制作一把石刃和一面石盾，合计至少需要 **5石料＋4纤维**：先用4纤维编成2束，再分别制作装备。若还要比较第二把同款石刃，再补2石料＋2纤维。资源来源仍须真实采集/拾取，不是每开一次台就免费发放。

装备定义来自本轮独立复制的配置资产：主手能力模板 `temporary-a.vc02.main`，盾类模板 `vc02.shield-a`。复制的是作者定义，再赋本轮新定义ID；新成品通过显式工厂产生新 `EquipmentItemState`，不会复制玩家正在使用装备的磨损、冷却或能力资源。图标是本机参考图：石刃暂用spear图标、石盾暂用rocks图标、纤维束用rope图标，不冒称这些就是最终石刃/石盾美术。

只扣 `team` 中合法、未预留的普通物品。安全栏、后备、手槽、外箱、地面和商店物品不自动参与。最终容量在候选扣料后重新布局，因此消耗整堆腾出的格子可以用于成品；仍放不下则整批拒绝，不能先扣再把装备丢地。已装备装备不能作为本轮材料。

## 5. 界面提示怎么处理

| 提示/现象 | 操作 |
|---|---|
| 没有配方 / 未接入设备 | 检查是否来到拒绝样板；作者检查supported与能力目录。 |
| 可用数量少于背包看见的数量 | 看物品是否在team，以及是否被其他合法操作预留；安全栏等不算材料来源。 |
| 数量无效或超上限 | 填正整数；样板maxBatch=8。数量框只是草稿，不会因输入回车直接制作。 |
| 最终空间不足 | 退出面板，按Tab整理团队网格/装备已有物品，再重新预览；不能靠预览绕过容量。 |
| 制作票据、库存或访问已变化 | 当前材料/角色/工位条件有变化，重新选择/刷新预览后再确认。 |
| 操作者或装备台失效 | 离开、高度/遮挡、死亡、受控状态变化、工位停用等会关闭会话；恢复合法状态后重新打开。 |
| 保存失败 | 按原共同保存提示重试保存；不要重新合成来“重试发奖”。保存和跨场失败的实际行为以原宿主回执为准。 |

重复收到已完成请求的回执只重读旧结果，不再次扣料或新增一件装备；这不代表可以拿任意旧ID提交新合成。当前预览与会话之外的请求会被拒绝。

## 6. 作者新增一个同类配方

新增普通材料配方，或使用**已经实现能力和表现**的装备制作配方，可以通过SO与目录配置完成，不改CharacterRoot/C#。新增此前没有的武器行为、护甲槽、附魔或队列机制仍需要对应实现，不能只加一张图标。

### 6.1 先准备原库存定义

1. 在自己的内容目录创建或复制一个 `ItemDefinitionSO`。当前Create菜单的历史名称是 `OSSASTRA/Items/Healing Definition`，类型仍是通用 `ItemDefinitionSO`；普通合成材料保持 `equipment=null`、`useKind=None`，设置新稳定definitionId、名称、图标、格宽高和堆叠上限。
2. 如果产物是新装备，独立创建/复制 `OSSASTRA/Equipment/Equipment Definition` 的作者资产。复用已支持的actions、abilityBindings/skillLoadout和Spine/显示配置；不要从Play中的装备实例或真实存档复制运行状态。
3. 新装备的Item与Equipment使用一致definitionId；Item.equipment引用该独立EquipmentSO。主手设置mainHand=true，副手使用相应offhandKind；装备由库存冻结为单件堆叠。不要为了配方修改原共享武器定义。
4. 将ItemSO显式加入每个参与场景的**原 `InventorySession.catalog`**，不是额外新建一套Crafting库存。材料和产物都必须引用catalog中的**同一个SO对象**；同名/同ID的另一份SO不算合法引用。

### 6.2 创建配方SO

Create → `OSSASTRA/Crafting/Recipe`，建议放在 `Assets/OSSASTRA/Crafting/Configs/` 或明确的自有内容目录。

| Inspector字段 | 填写要求 |
|---|---|
| recipeId / version | 稳定且唯一ID；初版version=1，改变结算内容递增版本。 |
| displayName / category / description / icon | 玩家可读名称、显示分类、说明和图标；分类不是资格。 |
| stationCapability | 与工位capabilities完全一致的能力字符串，如`equipment`。 |
| maxBatch | 正整数，样板8；不是无人值守无限制作。 |
| ingredients | 原catalog普通物品SO＋正整数数量；不能是装备、空引用或0/负数。 |
| outputs | 原catalog产物SO＋正整数每份数量；装备独立单件创建。initialDurability只用于新装备。 |

点击配方Inspector的“验证当前配方”。该按钮冻结配方本体，不会自动给Root登记或证明角色能用成品。然后把同一个配方SO加入明确 `CraftingRoot.recipes`。

### 6.3 配工位定义与实例

1. 需要新能力时创建 `OSSASTRA/Crafting/Station Definition`：definitionId、displayName、capabilities；正常工位supported=true，拒绝样板使用false和清楚的unavailableReason。
2. 将工位定义加入 `CraftingRoot.stationCatalog`。同类台A/B可以复用同一个定义SO，场景实例各有自己的instanceId。
3. 在场景复制一个本轮工位样板或放入自有模型，保留CraftingStation组件；替换`ReferenceVisual`外观时，同时核对Collider、interactionAnchor、layer/obstacleLayers和可见性登记。二维视觉指定独立billboardVisual子层；不要把Collider放在会旋转的视觉子层下。
4. 新复制的场景实例先**不要加入Root.stations**。手动清空它继承的instanceId，再点工位Inspector“为该未登记实例生成新ID”。按钮只接受Edit模式、ID真正为空且尚未登记的场景实例，不改Prefab资产，不覆盖已存在ID；支持Undo并标记场景dirty，不自动保存。
5. 设置mapId与当前Root一致、definition引用stationCatalog中的同一SO，指定自身层级内interactionAnchor，以及至少一个enabled、非Trigger、自有Collider。然后显式加入 `CraftingRoot.stations`。
6. 运行菜单 `OSSASTRA/Crafting/Validate Active Scene`，或Root/Station Inspector“验证配置”。修完明确报错后手动保存场景。菜单只读校验，不自动绑定服务、生成第二库存根、保存场景或进入Play。

校验会检查唯一宿主、原库存/Commerce/View/Map/Camera引用、重复ID、配方数量/定义/能力覆盖、同SO引用、实例地图/锚点/自有碰撞和视觉分层。它不能代替最终装备表现、真实输入、保存重开与可见性/净空的运行验收。

### 6.4 Main / Transit目录与存档约束

两场必须保留同一套**全局物品catalog、Root.recipes和stationCatalog**，即使中转场没有工位，也不能删掉恢复历史回执所需的目录。`stations`是本场实例登记，可以不同；`mapId`按本场身份配置。

合成通过原Commerce共同快照的`ossastra.crafting` section保存有界回执，材料数量/位置与装备状态仍由原库存保存。配方版本、成本、产物、初始状态、工位能力等进入目录指纹；目录不一致、未知/缺失section或不兼容版本会拒绝恢复，**不静默用新配方解释旧档，也不自动补播种**。

修改结算定义后用新的、显式非默认测试profile，并确认绝对目录与全部保存宿主再Play；保留旧profile，迁移需要单独设计。本轮`PrePlayGuard.cs.txt`只为CRAFT-01三个指定测试profile服务，不是任意作者profile的一键通行器。不要为了让验证夹具通过而换回默认`commerce-main`。

最后用普通路线验证：采集→F拾取→台上预览→整批制作→Tab原背包装备→实际使用→共同保存→重开同一物品。调试补料和直接调用工厂只能辅助诊断，不能替代玩家路线。
