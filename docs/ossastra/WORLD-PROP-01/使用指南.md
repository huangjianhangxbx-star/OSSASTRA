### 一次正常闭环

1. Play后走近出生区标为可破坏的二维石头或植物，用原主手攻击。未受击时不常驻显示耐久条；受击反馈只摇动视觉子层，条读取真实Health。
2. 石头默认60耐久、植物20耐久，实际伤害和多段依原动作，不硬算固定“命中次数”。归零后完整物体与它拥有的碰撞停用，掉落出现在合法同层支撑点；不会直接加进背包。
3. 先按Tab查看数量，关闭背包，走近落物按F，再开Tab确认“石料”或“植物纤维”及数量变化。一次按下处理一个完整stack，满包失败应保留地面来源。
4. 换成另一名角色攻击立体石块，重复拾取。旁边不可破坏对照不扣耐久也不出资源；伙伴没有新增自动采集搜索。
5. 留一块部分耐久石头、一份未拾掉落和一份已拾物，保存并去中转、再返回。正常加载不重置已保存耐久、耗尽或已交付回执；若配置/档案不兼容，会明确拒绝而不是重播种。

正常拾取仍复核当前主控、生命/输入资格、同层、距离、遮挡和容量。界面显示并不代表访问资格；站在高台下不能隔层取物。破坏提交和外观反馈有区别，掉落无法合法摆放时保留同一Pending，不能因没有画出物品就补发另一份。

## 2. 配置入口和参数归属

| 入口 | 配什么 | 不存什么 |
|---|---|---|
| `Assets/OSSASTRA/WorldProps/Configs/resource-stone.asset` | 石类可破坏定义，默认60耐久，掉落`world-stone`×3。 | 每个实例的剩余HP、已耗尽标记。 |
| `.../resource-plant.asset` | 植物类定义，默认20耐久，掉落`world-fibre`×2。 | 自然再生计时；本轮默认不再生。 |
| `.../resource-fragile-plant.asset` | 新增单击作者样本，8耐久，掉落`world-fibre`×1。 | 不覆盖20耐久定义或旧档进度；原输入单击及F已验；恢复与边界见报告。 |
| `.../decor-stone.asset` | `destructible=false`的装饰对照。 | 假血量或“打了但不发奖”的隐藏旁路。 |
| `.../world-stone.asset`、`world-fibre.asset` | 原ItemDefinitionSO：名称、图标、格尺寸/堆叠、重量等真实库存定义。 | 自建采集数量；数量仍归原Ledger。 |
| 场景唯一`WorldPropsRoot` | mapId、definitions全局目录、props、原commerce/inventory/coordinator/camera，有界奖励预算与重试间隔。 | 第二个Current、独立钱包、另一个存档writer。 |
| 每个`WorldPropRoot` | instanceId/lifeGeneration、definition、视觉子根、碰撞、同层support/supportSurface/surfaceId、安全掉落锚点、可见性组。 | 可随意改写的第二份hp。Play中Inspector真实状态仅供观察。 |

`WorldPropDefinitionSO`可从 Create → **Ossastra / World Props / Definition** 创建；`drops`中的itemDefinitionId必须已登记到同一InventorySession catalog。未知定义不发“空物品”，而是拒绝并保留既定待交付意图。音声字段是既有GameAudioRoot事件语义；留空不播放，不能为每棵树新建AudioSource。

二维`faceCamera=true`随观察yaw调整视觉子根；三维保持实体外观。缩放/晃动应放视觉子层，不移动逻辑根或Collider。`WorldPropView`只在受击期间被中央活跃队列推进，不自行扣耐久或发奖。

## 3. 制作一个新物件

下面是作者操作，不是运行时迁移。新作者布局应先选**全新隔离profile**；不要在已经保存过该地图的正式档上随便新增/换ID后期待自动重生。

1. 在Edit模式拖入`Assets/OSSASTRA/WorldProps/Prefabs/WorldProp_2D_Template.prefab`或`WorldProp_3D_Template.prefab`，也可复制当前样板物件。两模板已原生保存并回读内部引用；外部support被清空，必须按新场景重新接线，不能直接当作已配置好的资源点。
2. 复制/创建定义SO，设置唯一definitionId、version、最大耐久、destructible、掉落条目；给原InventorySession catalog加入所用ItemDefinitionSO，并把新物件定义加入WorldPropsRoot.definitions。共享SO只存作者配置。
3. 在新场景副本的WorldPropRoot Inspector点击 **“为选中新副本分配新实例ID”**。这只适用于尚未进入存档的新副本；不要给旧物件更换ID以刷新资源。运行时不会偷偷修复重复ID。
4. 保留独立VisualPivot/Body子层并替换Sprite或Mesh/材质；`visualRoot`必须是物件根的子对象，不能指根自身。配置ownedColliders为该物件实际拥有的受击/移动碰撞；不要把整个地形或邻居Collider列进去。
5. 指定稳定surfaceId与同层SafeDropAnchor：固定地面接`support`实际Collider；可重建高台接`supportSurface`的稳定GroundSurfaceBinding，由放置器每次读取该绑定当前capCollider。高台不能只保留已销毁的旧缓存Collider，更不能接下层大地。Binding失效或有限候选均不合法时保留Pending，不能跨层兜底。
6. 若参与现有遮挡：二维沿样板已有DecorationCutout兼容材质，不能换成该后端明确不支持的Sprites/Default后忽略报错。配置SceneOccluderGroup显式members/volumes并加入SceneVisibilityRoot.groups；把应参与贴墙净空的自有Collider加入两角色CharacterEnvironmentClearance.environmentSolids。破坏时同一拥有关系停用，不能遗留隐形代理。
7. 执行菜单 **XingHai → World Props → 登记当前场景物**，检查无重复ID，再保存新场。此菜单只登记逻辑props数组，不会替你添加定义目录、可见性组或角色净空列表。
8. 在全新验证profile中Play，按原攻击→观察真实耐久→破坏→F→Tab验证；二维与三维分别换外观验证一次。新定义若不在全局目录，或访问过地图的记录缺失，应明确报错而不是发一批新资源。

### 三维与参考素材说明

本场立体石块确实来自《开拓物语 Demo》的30顶点/32三角体积网格，原局部几何/UV在本机研究目录中；Unity材质、缩放、碰撞及通用破坏表现属于我方适配。二维石/草沿DS定向首帧和源pivot资料，不把整张动画sheet装成一个物件。

KT草原Plane的UV0是完整0..1，没有来源支持的局部裁切Rect；不因贴图有其他图块就猜一个“原本未用区”。精确原Mesh/UV、我方明确标记的SpriteRect改编与自主美术裁切是不同结果。本轮没有据此假装已复刻原Shader采样。
