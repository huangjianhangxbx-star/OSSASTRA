# KT-GROUND-01：原作地表组成研究

这次直接读取《开拓物语 Demo》安装资源，确认选定的 Starter 地图使用 **Unity 原生 Grid、七层 Tilemap 与 RuleTile** 表达自然地表。它不是仅凭截图推测的 Terrain，也不是本轮自行逐格创建 Quad 的方案。

本文只公开结构结论和验证方法。原规则数组、逐格布局、原脚本、Shader 编译内容、图集及派生媒体只保留在本机研究目录，不随这份摘要发布。

## 证据范围

源安装为 Steam Demo build 26043868；UnityPlayer 产品版本为 2022.3.60f1c1，采用 IL2CPP。使用本机已有 UnityPy 1.25.4 读取容器，先查索引，再读取选定地图及其直接地表依赖。没有启动原作、修改安装或存档，也没有全量导出游戏。

本轮证据等级如下：

| 等级 | 含义 |
|---|---|
| SOURCE_VERIFIED | 从所选源对象、引用、属性或解码像素直接取得 |
| INFERRED | 与用户截图或技术意图的合理对应，尚无直接运行证据 |

Starter 的资源证据不能自动证明营销截图拍自同一地图。这里也不把此前《饥荒》研究样地的 Unity 实现，当成《饥荒》原生引擎使用 Unity Tilemap 的证明。

## 已确认的组织关系

选定 Starter 的自然地表分七层，每层都有原生 Tilemap 与 TilemapRenderer，分别绑定对应的地表材质。各层共享边缘 Sprite/邻接规则，材质再提供不同的草地、深色地面或浅石道路底纹。

实际引用关系为：

`Grid → 地表层 Tilemap → RuleTile/Sprite → TilemapRenderer/材质 → 边缘图集及地表底纹`

这里的 Sprite 是图块资源，Tilemap 是作者数据与格子组织，TilemapRenderer 负责渲染。不能因为最终渲染需要几何数据，就把这套作者数据描述成自行摆放的独立 3D 地块模型。本轮未捕获原作运行时生成的完整网格或 GPU 批次。

草地内部、草地与道路交界、多色复杂边缘三个保存位置，都沿实际引用核对到对应 Sprite、材质和纹理；没有用建造道路模板冒充自然地面的证据。公开摘要不附源坐标、完整布局或对象反向映射表。

## 格距、边缘与颜色

源 Grid 的格子设置、坐标 swizzle 和父缩放共同形成 **4 个世界单位的逻辑格距**。边缘 Sprite 为 128×128 像素，PPU 为 **99**，居中 pivot；在源父缩放下，完整 Sprite 矩形的视觉跨度约为 **5.1717** 个单位。逻辑格与图像矩形不是同一尺寸，边缘存在伸出和重叠，不能为了“四米一格”把 Sprite 强行压成四米。

共享 RuleTile 包含 **14 条有序规则和一个默认结果，共15个 Sprite**。这是本次读到的具体规则组织，不把它改称《饥荒》的四角方案或另一套常见图块数量。

规则回读以七层全部 **7959 个已保存地块** 为样本：根据各层真实占用邻接重新计算规则结果，再与源缓存的 Sprite 和旋转矩阵对照。**7959/7959 均一致。** 这验证了所选布局的规则解释和方向，不能扩大成对所有地图、未来任意图形或原作运行时全流程的认证。

七张实际底纹中已经画有不同的草叶、石粒、冷暖深浅和部分小白花。所选 Tilemap 与地块颜色记录均为白色，因此不能把这些纹理中已有的差异全部解释成顶点染色。Starter 同时存在独立花草物件；这说明“花一定全画在地面上”也不成立，用户截图中每一簇花的准确来源仍需分别确认。

## 原图集与批次边界

15 个边缘 Sprite 实际共用一张 **1024×512** 图集，打包没有旋转。按源矩形、pivot 与 PPU 保留切片后，对原图集 PNG 的15处切片与独立 Sprite 解码输出逐一比较，**RGBA 四通道逐像素一致**。切片验证包括 Unity 左下原点与 PNG 图像坐标的转换。

因此本工程使用同一原图集进行 Sprite Multiple 导入，避免把15张独立 PNG 当成15张纹理而引入额外纹理切换。共用纹理只去除这一项批次阻碍；七层材质、Tilemap Chunk、排序、相机和渲染管线仍会影响实际 Draw Call，不能据此声称原作或适配场景“只有一次绘制”。

像素等价不等于恢复了原作的全部 Sprite 紧密网格、运行时 Tilemap 网格或完整渲染器。

## 保留的未知

源 Shader 只取得编译后的结构与属性绑定，没有原 HLSL 或 ShaderGraph。可以确认材质有底纹、遮罩裁切、光照相关属性和数值为16的缩放参数；**不能仅凭属性名和16这个值，断定世界空间每16米重复**。精确 UV 算式、完整 Lit/Ramp 光照以及原作者的编辑器笔刷流程仍为 UNKNOWN。

本工程的16m候选周期、自有 Unlit Shader、满覆盖底层、世界边界裁剪、三倍面积示范布局和 Scene View 刷地工具，都是显式的 UNITY_ADAPTATION。具体对应见 [源事实与 Unity 适配](source-to-unity.md)。
