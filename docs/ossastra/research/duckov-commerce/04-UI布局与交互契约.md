# UI 布局与交互契约（COM-00）

这份契约把**当前 Three.js 原型源码**作为可计算的布局/操作基线，并以 1440×900 的[定向浏览器画面](evidence/prototype-ui-observation.md)核实背包、商店和芙蕾菜单确实出现；把鸭科夫定点 IL 当成交互结构参考。它没有原作运行截图或 Prefab 几何，因此下表的百分比是**原型**位置，不是“鸭科夫原版高度还原”的证明。星骸已有视觉设计不因本次研究自动替换。其他证据见[原型 UI 源码](evidence/threejs-ui-static.md)、[原型功能](evidence/threejs-current.md)、[原作 UI 绑定](evidence/duckov-ui-static.md)及[Unity 现状](evidence/unity-current.md)。

## 布局坐标与缩放

## 输入/窗口公共规则

- **单一 F 仲裁**：当前 Unity `InventoryInteraction` 已处理地物与箱；商人与芙蕾能力纳入同一按键决策。一次按键最多打开一个目标或成交一笔；已打开交易时 `F` 只在无数字框焦点和有效报价时确认，不触发世界拾取。
- **捕获和退栈**：窗口持有独立 owner 调既有 `SetInventoryCapture`/`SetInputCapture`；数字框/确认高于商店，高于背包，高于世界。Esc 先取消数字框或拖拽，再退详情/商店/背包；关闭的同次按键不生成角色动作，释放自己的 owner 而不清掉其它窗口捕获。
- **移动与战斗**：沿当前获准的背包输入政策验证开包时移动和已受理动作的行为；交易 UI 不调用 `Time.timeScale=0` 代替输入隔离，也不顺手改控制、动画或音频。
- **失败可读**：显示单价、总价、数量、库存、币来源、容量/重量及具体拒绝原因。报价、提交成功、保存中与保存失败是不同 UI 状态。按钮灰显只是预览；确认仍由领域重验。
- **分辨率门**：至少以当前常用桌面分辨率及一档较窄分辨率检查区域重叠、滚动、商品网格、文字换行、焦点和指针命中；比例表是起点而非验收截图。

## 确切缺失的参考画面

工作区与下载目录未定位到用户提及的 PPT/PPTX。原作在本轮没有隔离存档可安全试玩；其 DLL 字段不能生成可靠的真实布局。若用户已有材料，最有价值的是**同一分辨率**下以下屏幕/短录像，而不是重做全套设计：

1. 普通商人：未选商品的整屏、选中商品购买详情、选中背包物品出售详情，各一屏；再录一次数量修改、缺钱/满包拒绝、Esc 退栈。
2. 容器：打开箱子并显示玩家包/目标箱、拆分数字框、拖拽非法落点/满包反馈，各一屏；录一次取消和取/存全部。
3. 地面：拾取提示、主动丢弃后世界代理、拾回，以及重进/重启同一状态的短记录。
4. 芙蕾：现有星骸原型/设计稿中角色菜单、对话、个人商店的预期最终画面；原作没有可直接推导的专属芙蕾页面。

这些资料缺失会阻止宣称“原作布局/操作已还原”。纯规则和宿主适配的技术方案仍可审阅。原型的三张实画面及内存取景说明见[定向观察](evidence/prototype-ui-observation.md)；本轮没有实际成交、对话、外箱或原作动态 UI 复现。
