## 下一轮最值得追的 10 个锚点

下表 token 都来自本轮真实 `methods.csv`，括号内为 DLL：Core=`TeamSoda.Duckov.Core.dll`，ItemStats=`ItemStatsSystem.dll`。

| 优先 | 精确方法 / token | 为什么从这里继续 |
|---:|---|---|
| 1 | `ItemUtilities::AddAndMerge(Inventory,Item,int)` `0x06000931`（Core） | R2：枚举吞掉 `AddAt=false` 后仍返回 true 的条件，以及堆叠分支。 |
| 2 | `ItemStatsSystem.Inventory::AddAt(Item,int)` `0x060000E4`（ItemStats） | R2：核查已有占位、容量与 parent 校验如何保证唯一归属。 |
| 3 | `ItemStatsSystem.Inventory::GetFirstEmptyPosition(int)` `0x060000E2`（ItemStats） | R2：`content.Count <= start` 分支未比较 Capacity；与 1、2 联合看可达性。 |
| 4 | `ItemUtilities::TryPlug(Item,Item,bool,Inventory,int)` `0x06000939`（Core） | R2：装备槽、合堆和 `Slot.Plug` 结果处理。 |
| 5 | `ItemStatsSystem.Item::Combine(Item)` `0x06000185`（ItemStats） | R2：堆叠合并、剩余数量和实例身份。 |
| 6 | `ItemStatsSystem.Inventory::RemoveAt(int,Item&)` `0x060000E5`（ItemStats） | R2：旧持有者移除、失败回滚与通知。 |
| 7 | `InteractableLootbox::StartLoot()` `0x060007D9`（Core） | R3：搜索/开箱入口与生成时机。 |
| 8 | `Duckov.Utilities.LootBoxLoader+<Setup>d__29::MoveNext()` `0x06002DF7`（Core） | R3：箱内实例化、`AddItem` 与溢出 `Drop` 条件。 |
| 9 | `Duckov.Utilities.LootSpawner+<Setup>d__20::MoveNext()` `0x06002DF0`（Core） | R3：世界战利品生成和随机配置入口。 |
| 10 | `LevelManager+<CharacterDieTask>d__135::MoveNext()` `0x0600298C`（Core） | R3/R6：尸体、丢弃和保存分支。 |

**R2 直接起点**：先对 Core `0x06000931` 与 ItemStats `0x060000E2/0x060000E4` 做定点 IL 分支矩阵，核查 `AddAt` 拒绝后上层返回和事件；随后接 `TryPlug`、`Combine`、`RemoveAt`。**R3 直接起点**：从 Core `InteractableLootbox::StartLoot` `0x060007D9` 反查 `LootBoxLoader.StartSetup` 的调用时机，再追异步状态机 `0x06002DF7` 的实例化/容器入库/地面 Drop 分支。若文件 SHA 未变，直接复用本轮索引，不必重新全量扫描。继续只读静态 R2/R3 **不需要新的用户决策**；运行游戏、安装工具、读取真实存档或做探针应另列最小操作并取得针对性许可。
