## R1 已验证的临时扫描器

R1 随后在本研究目录的 _work/metadata-scan/src/ 构建了 net9.0 的 MetadataScan CLI。它只读 PE/CLI 元数据和方法 IL，不使用 Assembly.Load，也不执行游戏代码；仅依赖 .NET SDK 内置库，没有 NuGet 下载或全局安装。完整命令、CSV 契约、测试结果见 扫描器说明（本机中间材料，未发布）。

- 生成索引：对 CLI 传入 --out 输出目录和一个或多个 DLL 路径；输出 types.csv、fields.csv、methods.csv、calls.csv、field_access.csv。三份核心 DLL 已全部扫描，SHA-256 与本基线一致。
- 定点 IL：传入 disasm、DLL 路径及该 DLL 的 MethodDef token（0x06xxxxxx）；stdout 为含指令偏移、操作码、操作数与可解析目标的 JSON。
- 实际验证：verify.ps1 的自造样例集成检查通过；本程序集 19,963 条 MethodDef 引用均可连接至 methods.csv。工具路径及原始扫描产物都在 _work/metadata-scan/，属于临时取证，不是可公开的完整源码。
- 限制：这仍是元数据/IL 索引，不是 C# 反编译器。callvirt 记录静态引用，不证明虚派发目标；字段写入表只捕捉 stfld/stsfld，容器变化需要继续追集合调用。定点反汇编尚不输出异常处理表、局部变量签名或跨程序集引用解析；遇到 leave 等控制流需额外核对。

## 可做与不能直接做的事

- 已验证：对 Managed 中 201 个 DLL 逐个读取 PE/CLR header，并计算 SHA-256；三个优先程序集的 CLI AssemblyRef 可读。游戏 DLL 没有被加载执行。
- R0 时确认 System.Reflection.Metadata 可用于列类型、成员、元数据 token 和原始 IL；R1 扫描器实现了这些索引。它不会自动给出可靠的 C# 反编译控制流、运行时调用图或行为结论。权威写入点仍须由方法体、调用方和必要的 IL 交叉核查。
- 如后续确需 GUI/CLI 反编译器或 Unity 资源解析器，应先确认本机其他已装路径或另行取得安装许可；当前不把缺失工具伪装成已运行。
- ScriptingAssemblies.json 是 Unity 的程序集登记；DLL 文件名与 AssemblyRef 只能提供导航。game_core_candidate、game_domain_candidate 等 CSV 分类是启发式，不足以证明“负责库存/任务/保存”。
- 静态代码也可能无法单独确定运行时配置、随机种子、事件先后、序列化实效或 Mod 覆盖。未读游戏存档和用户私人数据；未启动游戏或使用模组/探针。

## 可复核的只读方法

在 PowerShell 中对指定原文件使用 Get-Item、Get-FileHash -Algorithm SHA256；读取版本信息用 Get-Item 的 VersionInfo。对托管 DLL 使用 System.Reflection.PortableExecutable.PEReader 检查 HasMetadata 与 PEHeaders.CorHeader；AssemblyRef 由 System.Reflection.Metadata.PEReaderExtensions.GetMetadataReader 读取。[程序集清单.csv](程序集清单.csv) 包含逐 DLL 指纹，研究时先对照其 sha256。

R0 工作只写 参考游戏研究/逃离鸭科夫 内的基线文件与 ZIP 原文副本。R1 工具和扫描输出也只落在该研究目录的 _work/ 中。未触碰游戏安装目录、Steam 配置、存档和 Origin 工程，也未提交或推送远端。
