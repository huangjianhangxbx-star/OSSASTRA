## 已解决与未解决的取证问题

1. **已解决：版本误判。** 本机 Origin HEAD 旧于在线当前提交；所有原型现状结论以 `bb969cc` 为准。Unity 本机 HEAD 与其 origin 一致，但工作树脏，审计同时记录工作树。研究 DLL 指纹未变化。
2. **已解决：旧报告不能代表交易。** 本轮追加了商店报价、付款/发物、出售/返款、拆分/合堆、仓库缓冲、保存键与 UI 绑定的定点 IL。详情是[交易证据](evidence/duckov-static.md)。
3. **尚缺：原作动态与资源配置。** 没有隔离测试档，所以未验证具体商人商品、`PriceFactor`、现金/账户开关、所有失败分支的可达性、UI 几何、重启恢复；`AddAndMerge` 等只记静态调查点。
4. **原型 UI 已部分实测，仍缺完整操作。** 工作区没有找到用户 PPT/PPTX。最初从默认 `/` 启动停在“正在进入回廊...”加载页；按版本内启动测试改走 `/?scene2d=1`，在 1440×900 浏览器成功到达 battle，并观察[背包、普通商店与芙蕾菜单](evidence/prototype-ui-observation.md)。取景时只在页面内存中移动角色、加 1000 枚测试钱币；未实际成交、进入对话或个人商店，不能把三张画面当完整交互验收。观察截图和两张失败尝试的标题/加载图仅本机保留，未随本发布目录收录。
5. **尚缺：Unity 运行验证。** 没启动 Editor 或编译。场景/Prefab 引用只按保存的 YAML 静态判断，当前恰好两角色的会话约束与 dirty 场景必须在正式实施前重新确认。
