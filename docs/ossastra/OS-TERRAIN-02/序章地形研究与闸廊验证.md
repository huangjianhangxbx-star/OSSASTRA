# Never Grave 序章地形结构与裂谷闸廊验证

## 序章的基础结构

本机发行数据标记为 `v1.3.5c.s0.2335200`。该版本的 BuildSettings 把 `level3` 登记为 `Assets/__Mv/Scene/MvScene_0005_Tutorial.unity`。前一个 `MvScene_0003_Demo_OP` 只有过场装配，后一个 `MvScene_0010_Church` 使用不同的主要环境画片。教程场的蓝色遗迹、平台、链条和吊灯与用户截图吻合。截图的准确位置和由新游戏进入该场的调用还缺实机核对。

- `level3 #9717 Tilemap_Platform` 有 27,076 个占位格，共用普通 `MvTile_Platform`（`sharedassets3.assets#1157`），引用 8×8 的白方块 `MvSpr_White8x8_Center`（`sharedassets0.assets#566`）。序列化格颜色为 RGBA `(0,0,1,255)`，即蓝通道只有 1 的近黑色。启用的 Renderer 使用 Tile 图层和 Sprite-Lit-Default；Grid 为 1×1，同对象的 TilemapCollider2D 提供基本实体碰撞。
- 石边、背景、附着植物、吊灯、链条与前景分层画片另有实例。教程场扫描记录 2,132 个启用且可解析 SpriteRenderer，指向 136 个不同的 Sprite 引用，其中 `Mid-2_Gnd` 752 个实例。这是整个教程场范围的 Sprite 引用计数，包含环境外其他层。基础套件实际裁片数、纹理页数和每个截图的可见用料尚未逐一确认。
- 《丝之歌》开场下层样本的黑主体与独立饰边有相似的组织思路。该样本使用 `tk2dTileMap`（120×120，32×32 分区）以及分区渲染网格和 EdgeCollider2D，另有独立碰撞和 SpriteRenderer。Never Grave 教程场使用 Unity 原生 Tilemap。两者均需要将画面边缘与可走碰撞分开测量。[《丝之歌》本机研究记录](<E:/WORLDCREATOR/XingHaiHuiLang/Origin/docs/tasks/SV-MAP-02/README.md>)

## 运行时看的两套数据

教程场存有 7 个 `MvGm000_BlockFake` 和 7 个 `MvGm001_BlockThrough`。每个都有独立且初始启用的 BoxCollider2D 和两个 SpriteMask。将 14 个盒的位置读取到地图坐标后，盒内都没有已占用的基础格中心。这支持「基础地图先留出空间，策划对象单独挡路」的解释。

本机原生调用证据显示，`MvGm000` 的死亡／失活，以及 `MvGm001` 的破坏／等待状态，会到达 `MvGmMask.setMaskActive`。该方法切换遮罩子物体的激活状态或父级。已登记的部分地面和植被画片参与遮罩，基础 Tilemap Renderer 的序列化 MaskInteraction 为 0。在这条已核对的路径中没有观察到对基础格的 `Tilemap.SetTile` 调用。14 个物件的实际碰撞切换时机、用户截图处的对象身份以及离开重进是否仍打开，仍需原作动态证据。

地下城的房间生成是另一条路径。`MvStage_Graph` 整合已预制房间的 Tilemap，清掉接头和补平台，再向 `MvMng_Stage` 交付结果。村庄的家具建设另有占格和相邻边饰刷新逻辑。两条路径说明原作会在对应阶段改格或刷新外缘。一般玩法中任意挖掉基础格并自动重铺石边的行为仍缺证据。[发行方玩法介绍](https://www.pocketpair.jp/en/games-en/never-grave-en/) · [本机房间、村庄及原生调用证据](<E:/WORLDCREATOR/XingHaiHuiLang/研究/NG-TERRAIN-01/原作地形程序研究.md>)

最新对话里的水体截图可看到水线、水下覆盖及背景扭曲。教程场统计有两条启用且解析的 `Fx-Water` SpriteRenderer。排序、Shader 参数、采样路径及与角色入水事件的关系均待进一步核对。

## 在团结打开裂谷闸廊

场景 `Assets/OSSASTRA/SideView/PrivateValidation/OS-TERRAIN-02/PassageStudy/SC_BasaltPassageStudy.unity`。作者地图为「裂谷闸廊」，使用项目已有月白灰岩图件及一份独立的规则副本「裂谷灰岩」。场里有连接地面与洞顶的 2×4 闸墙、封闭小孔、台阶和前方下凹。打开场景直接 Play，底部选择「挖开缺口」「回填缺口」或「恢复初始」。Edit 时可以沿用 `OSSASTRA → 地形工坊 → 打开工坊` 编辑地图。实验里使用地图副本，退出 Play 恢复已保存地形。

实际 Play 从 341 格降至 333 格再回到 341 格。横向 Physics.Raycast 测到挡路物消失和恢复。新接通的底边和顶边只在开洞时生成，生成的 MeshFilter 有网格。角色在缺口时拒绝回填，复位后恢复原烘焙物体，作者地图仍为 341 格。运行时样板整次重建主体和饰边，需要验证大图性能后才能采用局部重建方案。本轮新生成饰边比原场 C 光照下更亮，尚没有进入同一套光照画片清单。后台鼠标因为 Game View 失焦被禁用，以上动作为 Play 中直接调用研究组件验收。

裂谷闸廊是原创研究布局，序章事实来自本机发行数据与用户截图。原作完整场景和素材库未拷入工程。原作实时变化验证仍缺事件前后录像、同一点的对象状态和碰撞对照。
