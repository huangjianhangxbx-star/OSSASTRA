# KT-VIS-06 验收矩阵与 Native 访问合同

本表是执行前的验收设计，当前各项均为 **待执行**，不能作为通过回执。实际结论由本轮验收报告逐项填入证据与限制。规格来源为同目录《设计说明》《实施计划》；继续同一 Lab，不重建地图或角色。

## 最小执行顺序

1. 纯 Core 的自然/有限/相机孔锥与纯呈现时序合同先执行 RED→GREEN。
2. Native 正式材质下执行 N00—N08，保存同一次主相机真实帧的权限、几何、时间与颜色证据。
3. 复用 05 的引用所有权与 V4 释放重接方法执行 N09—N10；最后保存重开及保护核对 N11。

只验证本轮改变及必须保持的边界，不重复全项目回归。`Stats.Active`、Shader 编译成功、域数量非零均不能替代最终画面。参数或字段缺失记 `BLOCKED/MISSING`，不能以空集合、未实际分配或默认值通过。

## 现有05候选的复用边界

- `FinalWindowProbe`提供原场定位和七种采样方法，**旧的outside-far/back期望不可照抄**；新自然策略及独立相机窗景改变了该期望。
- `FinalControlMatrix`提供原orbit、实际封板、SwitchNext与精确恢复方法，不可把旧有限域数作为本轮断言。
- `ScopedSourceReferenceContract`和`FinalLifecycleContract` V4必须保留原角色Coverage所有权与endFrame后观察方式；不得将有业务owner的自然短命对象死亡误报泄漏，也不得放过稳定源销毁。
- `VerifyContracts.cs.txt`仅做一个真实主相机endFrame的只读快照和新接口存在性检查；不定位、不封门、不切控、不停用Root、不写存档。其`fullAcceptanceExecuted=false`恒为false，所有N项依然需要上述独立证据。

## 本轮明确边界

“自然视野无限远”表示移除普通玩家6/8米限制，仍受真实孔洞、实体遮挡、当前空间和实际相机远裁面限制。相机窗景不代替人物感知；窗内当帧动态可见与信息权限是两项断言。静态世界域历史最多4份、约1/6秒取样为有界近似；门板/Current/传送/失效重置优先。屋顶与前墙自身仍硬切。Player、实体硬件、任意Mesh LOS、完整多层、全部PMA叠层、烘焙/反射/SSAO与最终审美未实际验证则如实保留。
