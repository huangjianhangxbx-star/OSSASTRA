## 为什么原作只显示一个面

原作 Build24935935 的静态链已复核，标记为 **STATIC_CONFIRMED / ORIGINAL_RUNTIME_NOT_RUN**：

1. Unit/Character 形成实际 forward，按 **XZ** 取方向，用 `atan2(x,z)` 选扇区；右向复用左向动画并镜像。
2. `Unit.Play` 设置主动作（默认轨0），方向动画设置到**轨9**。方向只写特定根的位置，高轨号不是专用“方向功能”。同名循环动作可能提前返回，但方向设置在这个提前返回之前；inheritTime 路径会继承动作时间。
3. `Unit.LogicLateUpdate` 先 RefreshRotation，再调用 `SpineUtil.手动更新遮罩`。当前调用没有传 tuple 缓存，因此逐次执行检查。
4. helper 从活动裁切附件求世界顶点的 AABB，检查**所有 slot 的骨原点**是否在矩形内，设置 `HideBy高级控制`。
5. 原作自定义 `Spine.Slot.get_A` 在 Hide 时返回0；渲染器读取这个 alpha。附件对象仍在，骨骼和约束仍然求解。

这不是逐帧“程序把所有零件抓回根骨”；搬面由已经做好的方向动画完成，程序主要做选面、镜像及显隐。隐掉图像不等于免除全部骨架 CPU 成本。独立浏览器内测得776骨的 state+world求解约0.10ms、494slot矩形分类约0.009ms；这只是本机 Edge headless/softwareGL 的 JS CPU 小样本，**不能当作 Unity 或原游戏性能指标**。

骨原点剔除与多边形几何裁切不等价：附件顶点伸出矩形时，前者可能仍显示完整附件。针对三个长兵器动作的15个进度采样，检查6483个附件姿态，未观察到“骨原点在内、顶点在外”；这不保证所有动作都无边缘问题。

### 文件里的裁切还有什么用

默认 `遮罩` 是第488个 slot（从0计），结束 slot 是自身。匹配版本官方 renderer 在 clipStart 后直接继续，因此这个自结束裁切作用于**后续直到骨架末尾**的部分，而不会回头遮住前面488个slot，也不是“作用范围为零”。默认顺序下后面只有5个slot。眼睛局部还有两处裁切，与选方向不是同一件事。

开头的 `scale` 裁切 setup 未挂附件；`_out / _出井盖 / _跳井盖` 会启用它，已做实际采样。不能把某个待机结论扩大成“源裁切永远不起作用”。裁切依赖绘制顺序和结束slot，而不是普通层级 Mask。[Spine 官方裁切说明](https://esotericsoftware.com/spine-clipping)

研究台用“临时清附件”实现原作矩形显隐的**画面对照**；原作实际为自定义alpha，两者不是完全相同的运行实现。a1/25%/左面时，可绘候选：源裁切376、原型中文清理238、矩形显隐32；这些不是GPU draw call或裁切后的可见像素统计。

## 选面、转向与动作时点

原作八向表有闭区间及顺序：右67.5–112.5、右下112.5–157.5、下157.5–202.5、左下202.5–247.5、左247.5–292.5、左上292.5–337.5、上337.5–22.5（跨0）、右上22.5–67.5；边界重合时先匹配者胜出。零向量明确回退左下。不能把这个角度直接当作屏幕右=0°。原作有区间扩张能力，但已核 Play/SetForward 调用未启用，未宣称这些路径有滞回。

转向不总是追鼠标：Character 的 banRotate 可以拦截实际转向；技能接受/释放、阶段再次采样、targetForward 与真实 forward 分开；部分技能强制特定面。独立实验验证了受击替换、同名动作重播、方向切换不重播主动作与不重复事件；**这不是原游戏全部技能、死亡、换装路径的实机验收**。

方向 mix=0 可直接归位；非零mix中旧根和新根穿过中间位置，可能进出显示矩形。研究台可重现，默认建议 DIR02 对离散面单独配置不混合；不得顺便改变身体动作过渡。短录屏见本机 evidence/04-direction-switch.webm。

## 碰撞、手和装备应该怎样理解

显示多个面不要求复制多套角色移动碰撞体。正式 Unity 的角色移动/命中由玩法根的世界空间数据管理；动画和面是表现。武器打击范围、弹体出生点可以从语义挂点取姿态，但不应拿可见图像代替伤害判定。

每面左右手已经实际求出世界坐标（含镜像），名字不随镜像互换。**“当前中文面里的手骨”仍不一定是辅助分支接管时应该挂武器的手骨**。本轮提供候选坐标和开关，不冒称已建立正式装备挂点表。原作 GetBonePos/GetBonePosition 本身只做精确骨名查询+世界变换，未证明它会自动展开每面名字；原作每种攻击碰撞配置没有在本轮穷举，仍未知。

独立装备 Spine 不会自动继承身体 Skeleton 内部裁切；正式接入要验证每面/动作的语义挂点、前后遮挡和独立装备显隐，不能只 FindBone 第一个同名手骨。
