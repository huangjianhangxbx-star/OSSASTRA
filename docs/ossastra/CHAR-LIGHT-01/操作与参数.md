# 角色光感：操作与参数

CHAR-LIGHT-01 v1.0｜2026-11-04

本模块让现有2D角色接收环境色、方向性细轮廓和强光保护。夜间可读度、局部受光、角色深度及房间观察许可继续由原系统负责。本文现行默认值采用用户本轮截图明确选择的参数；后续仍可调整，技术验证不代替其余画面与美术验收。

## 1. 从哪里打开

唯一主场：

`Assets/OSSASTRA/GroundWorkshop/Samples/KT-VIS-04/SC_RoomVisibilityLab.unity`

本轮接入保持当前35°机位，不另建平行主场。进入运行后，在原“环境模拟”窗口旁找到折叠的“角色光感”，点击标题展开。右侧有常显滚动条；下方还有恢复、保存候选和诊断内容。把指针停在控件上可看中文说明。

窗口顶部“观察 / 调节对象（不切主控）”只选择要查看和调节的角色，不移动它，也不改变真正的玩家主控。两名角色分别拥有运行参数，调一名不会同时改另一名。角色切控仍使用原游戏入口。

在面板内悬停、拖动、选择下拉或用导航操作时，会沿原协调器和地图接口捕获本窗口自己的输入，避免同时攻击、拾取或旋转镜头；离开交互、收起或停用时归还。没有新设备按键监听，Q/E仍是原技能。

## 2. 建议的第一次对照

1. 在“环境模拟”固定当前时刻和灯光，保持同一角色、姿态、机位与曝光。
2. 在“角色光感”选该角色，点击“旧效果”。它关闭三个新增效果，保留当前用户选定的环境受光与亮度保底，不把环境数值倒回任务接手时的M0基线。
3. 点击“仅环境染色”，观察同一个人的浅发、皮肤与深衣；不要换另一名原画颜色不同的角色来判断新旧差异。
4. 点击“染色 + 克制轮廓”，靠近暖灯并走远、转向和转镜头。细边应随有效灯和角色外形变化，无有效灯时不会成为常亮白圈。
5. 点击“一键恢复进入面板前状态”，或分别关闭三个效果核对对应旧路径。

“旧效果 / 仅环境染色 / 染色 + 克制轮廓”会改变当前观察对象的效果组合；参数取本次进入窗口时捕获的该对象数值。它们不是切换角色，也不是切到另一份原生Spine材质。

收起窗口只收起UI并释放交互，不自动撤销当前调参。要撤销请使用恢复按钮；本轮关闭再展开会重新捕获当前运行参数作为新的预览起点。

## 3. 环境染色为什么有两处强度

“环境模拟”中的“天空、环境底光与角色阅读”分组负责颜色来源：

- “手动覆盖天顶 / 地平线颜色”：选择手动天空艺术色。
- “覆盖天空色同步到角色环境光”：是否把这份手动天空色传给角色环境贡献。
- “天空与角色环境色联动强度”：这条颜色桥的全局强度。

“角色光感”中的“环境染色”和“环境染色强度”负责当前对象是否消费、消费多少。

实际响应强度由两处强度相乘，再受各自开关和合法环境状态控制。本机样板的组合是：天空联动强度`0.5` × 角色Profile响应`1`，得到`0.5`。用户本轮已将角色响应`1`确定为现行默认，当前主场、`CharacterLightingMeasured`及新建类型缺省均采用该值；先前类型缺省`0.5`只保留为历史。不要为了得到相同响应无意再乘一次颜色。

这里补的是“手动天空覆盖没有进入角色环境响应”的缺口。没有开启手动覆盖、关闭同步或强度为0时，这条新增颜色桥回到对应旧路径；自然昼夜原有的环境底光仍照常变化。

新染色只改变环境贡献的色度，再合入原太阳和局部灯，避免把暖灯再次整体染成天空色。室内保持原环境色及靠灯效果，不因为视觉揭顶变成室外。角色不必与金属球同色同强度：球体反射与手绘角色的风格化环境响应不是同一材质模型。

已有“角色最低可读度”和“角色/装备受光响应”仍在原环境面板。用户本轮明确选择的现行环境默认如下，Root已接回主场：

| 环境参数 | 当前用户选定值 |
|---|---|
| 环境底光倍率 | `1.99` |
| 室内底光系数 | `1` |
| 角色最低可读度 | `0.02` |
| 地表受光响应 | `2` |
| 装饰受光响应 | `2` |
| 角色/装备受光响应 | `2` |

这次选择覆盖先前“保留M0最低可读度`0.12`、室内底光系数`0.22`”的默认取舍；M0仍是历史对照，不再作为恢复目标。关闭新增效果或使用“旧效果”，均回到当前用户选定环境下的原受光路径，不恢复上述旧环境数值。其他未指定的环境数值及当前时刻保持。

## 4. 三个独立效果与参数

| 控件 | 实际作用 | 调节时看什么 |
|---|---|---|
| 环境染色 | 当前角色消费手动天空色桥 | 夕阳暖色、冷夜色；原画深浅不能被一层橙膜抹平 |
| 受光细轮廓 | 在完整角色自身外缘的内侧提亮 | 朝灯方向、细发丝与武器、双人交叠和墙边；默认外扩为0 |
| 强光高亮保护 | 对主体与轮廓合计光照增益的过亮段软压缩 | 增强灯光后仍有变化，白发、脸与衣褶不变白片 |
| 环境染色强度 | 当前对象0–1响应，与天空全局强度相乘 | 当前默认`1`，可与0关闭对照；不用它代替灯光亮度 |
| 轮廓强度 | 方向性细边贡献倍率 | 不应抢过脸与动作；无灯不应靠此值产生整圈光 |
| 内带宽度 | 最终画面像素单位，范围0.25–4 | 当前用户选定`4`，以正常游戏尺寸继续观察；不是图集像素 |
| 内带柔度 | 内侧过渡柔和程度 | 降低硬锯齿，但不做宽灰雾或向外扩光 |
| 轮廓贡献上限 | 额外轮廓的独立预算 | 强灯下不应再叠出刺眼白圈 |
| 保护拐点 | 线性光照增益开始软压缩的位置 | 太低会让正常光段变平；太高则强光保护过晚 |
| 保护渐近上限 | 强光增长逐渐接近的上限 | 必须大于拐点；系统统一校验，不逐通道硬截白 |

用户本轮选定并已写入主场作者Profile及新建类型缺省的参数是：环境染色响应`1`、轮廓强度`0.28`、内带宽`4`、柔度`1.23`。轮廓上限`0.35`、保护拐点`1.2`、渐近上限`2`保持。强度和保护参数属于线性光照增益空间，不是通用物理灯光单位或最终画面sRGB上限；内带宽则是最终画面像素。后续实例可继续调节，以实际对象诊断与Inspector为准。

完整轮廓按角色分别合成当前身体与装备覆盖，再服从原合法片元绘制；不能把墙遮住身体后留下的截线当成角色外缘。局部灯采用登记灯、房间/距离和保守实体遮挡资格，不代表已实现任意Mesh的逐像素附加灯阴影。

Bloom开关当前禁用并附原因。本轮没有新增或接管Bloom后端，基础效果应在不依赖Bloom的条件下成立。不要通过提高全场曝光、灯强或Bloom替代这些效果。

## 5. 固定时刻与恢复的范围

“固定环境时刻（世界不停）”只停止明确`EnvironmentRoot`的演示时钟。角色、AI、天气和业务继续运行，`Time.timeScale`不变。

若时刻由`External`外部来源负责，冻结控件会禁用。仅把`clockRunning`设为false不能阻止外部时刻采样，因此不会显示虚假的“已冻结”。

若先在本窗口冻结，随后被外部来源切换时钟模式，或被其他作者恢复推进，本窗口会撤销自己的过期冻结记录并取消勾选，不把旧模式或旧开关写回去。`External`模式下仍保持禁用；回到可控模式后，如需再次固定，应重新主动勾选。

“一键恢复进入面板前状态”恢复本次预览捕获的角色运行参数，并归还本窗口自己拥有的时钟修改。时钟若已被别处改成不同状态，不强行覆盖。它不会回滚另一个“环境模拟”面板里修改的天气、太阳或天空颜色，也不回滚角色位置、装备或游戏存档。

## 6. 调参和保存是两件事

普通滑条与开关只修改`receiver.Settings`运行副本，不自动改共享`CharacterLightingProfileSO.settings`。同一Profile可以被多个角色引用，每个接收者仍持有独立副本；运行调参也不偷偷写业务存档。

在Editor中点击“显式保存此对象候选Profile”，会另存一个新资产：

`Assets/OSSASTRA/CharacterLighting/Profiles/<ActorId>_Candidate.asset`

重名时使用Unity生成的唯一新路径，实际结果显示在面板状态里。此操作不会覆盖原Profile、不会自动替换接收者的Profile引用，也不会保存整个场景或所有资产。Player中该保存功能不可用。

要把候选作为下次启动的作者配置：先结束运行，在目标接收者Inspector中明确选择新Profile，再按正常作者流程保存相应场景/Prefab。当前运行副本不会因你临时换了共享SO引用而自动重建，不要把修改运行副本、另存候选和正式绑定三步当成同一动作。

保存按钮的实现与操作入口已存在；本文不将“按钮存在”写成资产保存重开已经验收。具体保存读回和整轮收尾结果以根任务实际验证记录为准。

## 7. 怎样读诊断

下方诊断显示当前对象、作者Profile/运行副本、登记成员、实际源Shader及可识别的alpha输入、轮廓灯资格、天空联动与角色响应乘积，以及缓存状态与显存量。

“等待合法相机绘制”“局部灯缺失/异室/距离或实体遮挡拒绝”是具体资格状态，不应靠调高轮廓强度绕过。没有详细服务回调时会明确显示未绑定，不凭UI推测房间、灯或GPU数值。

这些诊断描述当前登记和受控绘制的数据，不是逐像素真值测量，也不能据此宣称所有光照/材质/平台都通过。

## 8. 以后换原创角色怎样接入

1. 保留该角色原图、Spine源与正确的StraightAlpha/PMA输入合同，按项目现有比例与五方向工作流导入；基础功能不要求额外重画全套法线。
2. 在正式`Ossastra.Characters.CharacterRoot`所在对象添加可选`CharacterLightingReceiver`。指定真正的身体Renderer与明确GameplayCamera，不把血条、技能特效、深度代理或阴影代理列入身体。
3. 指定作者Profile。接收者首次访问时克隆参数，之后UI和渲染服务消费同一运行副本；不要由第二个脚本反复覆盖sharedMaterials或PropertyBlock。
4. 在现有`CharacterLightingSystem.receivers`和角色光感面板的显式列表中登记该对象，复用同一Environment/GameplayCamera与原RoomSight绘制链。当前覆盖预算为两名玩家角色；增加其他实体前先处理预算，不直接给全部敌人批量开启。
5. 原`CharacterRoot`在自身初始化与表现提交后推进接收者；五方向只捕获当前有效面。现有Spine/Sprite装备表现端口会跟随其生命周期纳入成员；自定义附件通过`RegisterAccessory`/`UnregisterAccessory`成对登记，脱手后不得留在旧人物轮廓中。
6. 用同对象旧/新A/B核对透明边、五方向/镜像、换装/脱手、两人交错与墙窗负例；关闭新效果应回对应原显示。深度、遮光和观察许可仍由原模块负责。

原生Spine材质保留为作者显式对照；本面板没有“切回原生材质”按钮。具体参考资产由根任务交付清单登记，本文不虚构路径，也不建议用两种原画的差异代替同角色材质比较。

## 9. 当前验证口径

本轮UI已有真实Native通过回执：22项结构/输入检查，以及15项参数写入、运行副本隔离、恢复、预设和时钟检查。它们验证控件确实操作了对应状态，并保留外部输入owner，不等于GPU画面或最终美术已经全部验收。

整轮的轮廓形状、透明度、光源方向、空间许可、运动录像、资源释放、保存重开、性能与未测平台分别由根任务记录。技术通过不替用户签“好看”。自动验证使用隔离测试档；收尾恢复原业务路由后不再进入原档Play，这与用户之后正常启动游戏是不同场景。
