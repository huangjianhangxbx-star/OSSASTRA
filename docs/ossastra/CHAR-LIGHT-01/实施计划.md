# 角色光感实施计划

目标：接续用户批准的CHAR-LIGHT-01 v1.0，在当前唯一35°主场实现角色环境染色、完整人物方向细轮廓与高亮保护。

架构：EnvironmentRoot/Frame仍为环境唯一来源；CharacterRoot只组织可选Receiver，运行参数由Receiver复制Profile持有。CharacterCoverageCache在RoomPositivePass生成逐角色完整alpha；颜色只在现有合法片元计算，RoomSight/深度/Caster权威不变。软肩作用于不含贴图与slot alpha的光照增益，最后乘原色，保留PMA与纹理对比。

技术：当前团结2022.3.62t16、URP14.2.0-t1、Spine4.3、DX11；原UniversalRenderer/后处理状态不变。本轮B级模块＋许可专项，不跑无关全游戏回归。

## 文件与执行顺序

1. M0：Native记录当前主场/环境/213 Renderer材质引用、35°/25/FOV35、原路由与dirty，外部安全副本；精确源/用户材质/四原档SHA。已完成，基线见本机研究/角色光感/CHAR-LIGHT-01。
2. M1：EnvironmentSkyBinding.ResolveStylizedSkyTint只解码一次Linear作者色；EnvironmentLightingGain仅给登记角色的室外ambient染色，之后再合主灯/局部灯。测试`Math/EnvironmentAmbientTintContract.cs.txt`：先旧路径暖/冷不变RED，接线后局部差值、室内、旧保底、禁用/alpha检查。已取得真实RED/GREEN。
3. M2：`Runtime/CharacterLightingReceiver`只登记明确身体及原装备端口；`Rendering/CharacterCoverageCache`每相机Pass持2个独立512²槽，真实当前网格alpha union，无场景截线输入。`CharacterLightingSurface`求有限内带，零alpha背景资格排除内部半透明接缝。`CoverageGpuContract`与`CoverageShapeGpuContract`运行真实GPU，坐标须独立校准，不能把ReadPixels行序假定当产品错误或正确。
4. M3：`Core/CharacterLightingSettings/ProfileSO`、`CharacterLightingColor.hlsl`提供Clone/Sanitize、环境色度、轮廓预算及合计gain软肩。`CharacterGainGpuContract`正式Spine/DepthPlane四alpha组合与`CharacterGainBoundaryContract`8灯/zero-alpha加色边界已有真实RED/GREEN；拐点/上限仍须主场扫值，不代签审美。
5. M4：`CharacterLightingSystem.Bind`在逐Renderer合法draw上传参数；仅复用环境显式点灯列表，同室/距离/三条OBB线段资格，15%滞回与短换灯衰减。`CharacterLightingRim.hlsl`把完整轮廓方向投影到当前相机，主灯复用真实阴影与云场。`HasClearSegment`开放/薄墙/高低/旋转/缺数据真实RED/GREEN；再测真实灯左右/投影近零、墙截线/未知房间/关窗、两角色与五面装备。
6. M5：`Development/CharacterLighting`独立折叠uGUI，有可见滚动条、提示、观察选择、三预设、恢复、冻结环境钟、显式另存Profile。测试先缺入口RED，再在隔离档Play测试真实控制值/owner输入/回退；原环境面板补天空同步总开关。复用当前光影观察区和房间，保留两原角色源材质及原生Spine显式参考，保存重开、3次启停、两段连续录像。
7. M6：记录实际差异/入口/换原创角色接入说明/资源预算/性能可取得值与未测项。必要验证完成后按R11精确发布本任务自有代码、合同与文档；场景/配置/源媒体/真实档只留本机，不Gitee。
