## 1. 两条结果分别成立

**异常切身排查：** 两张用户反馈分别复现、分类、记录证据。可能是物理位置/支撑错误、正式显示网格与环境相交、深度/排序问题或合法遮挡；截图不足以确定Collider已入墙。透视关闭时，已验证的开阔合法站位不应被脚下地面异常截身；实体墙仍限制移动。未修的异常单列，不靠透明遮掩签收。

**合法遮挡可读性：** 角色位于合法空间时，让镜头与角色之间的登记模型渐变透明。角色自身不被本功能淡化、染灰、置顶或复制成额外轮廓。关闭本功能时保留原本合法遮挡。

## 2. 视觉契约

统一使用`opacity`：0为不显示，1为原显示，避免“透明度”一词方向歧义。

| 状态 | 遮挡模型的结果 | 角色的结果 |
|---|---|---|
| 无实际遮挡 | 保持原颜色、深度和可见性 | 原显示 |
| 轻微遮挡 | 身体附近小范围柔边圆窗 | 本功能不降低alpha |
| 遮挡加深 | 清晰内圈和羽化外圈扩大 | 正常身体完整位于清晰核心，不裹灰膜 |
| 深度遮挡 | 显式许可的有限模型组可整组淡出至opacity0 | 仍是正常场景角色，保持真实前后关系 |
| 遮挡解除 | 滞回后平滑恢复 | 原显示保持 |

主效果必须是**平滑alpha渐变**；中央移除、羽化渐变、外围原样。不以固定硬洞、明显网点抖动、发光圈、雾、全屏滤镜或模糊替代。Dither只作明确标注的对照/降级；主效果未达标时如实记录，不改验收要求。

圆心来自脚点加配置身体高度、必要时结合当前有效身体范围，不固定在脚底。正常身体与贴身装备的显示分别诊断；隐藏方向面、未引用网格缓冲、长武器/瞬时特效不撑大身体核心。攻击和装备的实际范围另验，不能只露头就称完整角色清晰。

圆距在真实玩法相机viewport等距像素中计算，包含viewport偏移、RT尺寸和投影方向。至少两种宽高比、两档zoom仍保持圆形和身体覆盖；近裁面、负投影深度、离屏目标需保护。诊断圆线默认关闭，UI不参与透视。

## 3. 先做厚墙渲染小样，再冻结接法

M2首先以一段厚墙和现有Spine角色取得真实闭环，再扩高台。使用实际本机URP/Tuanjie/Spine版本，不升级包或照抄Unity6 RenderGraph。

| 路径 | 必须保持的行为 |
|---|---|
| 不透明外围 | 原正常颜色和深度，仍正确遮挡世界 |
| 透明核心 | 实际遮挡链移除，旧深度不能继续挡住身体 |
| 羽化带 | 在已经正确绘制的角色/背景上平滑混合，不成为灰膜 |
| 组内多部件 | 厚墙背面、顶盖、封口及需要参与的附件一起正确处理，不残留实心内部 |
| 多层地表 | 采用原实际可见表面或等价受控合成，不把每层都叠成一张透明膜 |
| 相机深度相关Pass | 所有实际启用的Forward/DepthOnly/DepthNormals等具有一致可见域；未启用者标不适用 |
| 世界阴影 | 首版保留明确的原阴影策略，不把Gameplay屏幕圆直接用作光源圆；修改ShadowCaster需另列依据与验证 |

禁止仅改`material.color.a`、保留旧实心draw再额外叠透明draw、全局ZWrite Off、角色ZTest Always或全部模型Transparent。渲染Feature/有限显示代理/材质接法须以小样证据选择；不能未经授权改全局Renderer列表或管线资产。受限分支停住时，继续不改全局的试验路线。

## 4. 职责与所有权

- 角色侧可选目标适配提供真实脚点、稳定身体范围、存活/可见状态和现有主控优先级；CharacterRoot管理适配，不反向依赖实验场，不改HP/动作/运动。
- 遮挡组显式登记Renderer、材质槽、检测代理、surface策略、整组淡出许可与恢复状态。完整世界根不能成为一个可完全淡出的组。
- 环境根通过现有接口读取主控及伙伴，不维护第二套当前角色，不新增相机控制者或第二次Move。
- 检测、程度/滞回、渲染参数、诊断各自职责明确。可合并深模块，不为图示制造空接口。
- 状态及临时材质/RT/Pass有明确所有者；退出、禁用、切场、重载时只恢复本模块仍持有的引用/属性，不覆盖其他写入者后来接管的值。不每帧`new Material`。

## 5. 检测与动态范围

检测依据必须独立于淡出后的颜色/深度，避免“开洞→检测不到→恢复→又遮挡”的自反馈。优先用未被本效果修改的登记代理。

首版约5个稳定参考点：头、胸、身体两侧、脚上方。沿真实相机投影到目标深度查询；正交相机使用各参考点的平行射线。忽略角色自身、无关触发器/交互体/未登记对象，处理一条射线的全部实际遮挡组并去重。

本轮探针选择对每个组的显式登记Collider逐一查询`Collider.Raycast`，并对支持形体检查射线起点内部，不用全场`RaycastNonAlloc`。显式登记的query-only Trigger可参与，普通未登记Trigger不参与。因此NonAlloc命中排序/命中缓冲饱和子条为不适用，不能冒称已测hit缓冲；每组全volume覆盖与Root活跃组预算溢出仍必须独立验证。非凸Mesh内部不靠Bounds猜，报告不支持的内部判定。

无碰撞树冠可登记独立查询代理，不改变攻击/运动层语义；树干细Collider不能代替整个树冠。近裁面和射线起点位于代理内部须定向验证，不能仅扩大检测半径掩盖问题。

强度由实际遮挡采样比例/投影进入量等归一化信息驱动，不能只凭AABB重叠淡出，也不能靠累积时间让静止物体无限透明。显示投影/平滑每帧更新，检测候选20Hz，快速镜头变化允许受控加测；进入/退出有门槛和短滞回。

“深入”是在合法空间中遮挡加深，不要求角色进入实体墙。退出、出画再入画、失活或无目标后正确恢复；重新入画在首次正式draw前取得正确参数。不能用`Renderer.isVisible`替代该Gameplay Camera的资格。

## 6. 支撑与多层高台

脚下支撑面默认保护，不因脚点接触顶盖就擦空承载地面。低地、顶盖、墙、桥面分角色登记，不跟随世界根整片消失。

低地角色被高台遮挡时，真正挡在前方的侧壁、必要顶盖/封口及附件可构成局部组；处理完整遮挡链。人在高台上时保留脚下支撑，透明不改Collider或实际站立高度。

若某平台承载主控同时遮住伙伴，首版优先保证主控支撑面可读，限制整组淡出，退回局部前景处理并记清限制；不能为伙伴可见让整片主控站立面消失。

## 7. 双角色、相机与玩法不变项

主控优先，同屏存活伙伴可保护，Inspector可关闭伙伴保护；默认上限2，敌人不自动注册。每组多圆使用并集/最大淡出需求，不最后写入覆盖，不反复相乘透明度。切人只改变优先级和参数需求，不清空全部历史。

死亡/失活按现有合法继任者交接；无合法目标恢复本模块状态。同一个洞自然露出的敌人保持正常深度，不修改索敌或伤害资格。

测试需区分原协调器的两条实际路径：死亡事件可触发原继任逻辑，GO失活先撤销不可用实控，随后可经公开`SwitchNext`交给存活成员。仅测试GO失活不能代签真实HP死亡事件或自动死亡交接；不得为完成测试直接改HP、伪造死亡或写第二份Current。

最终玩法相机、角色正式表现与mask投影必须在同帧有确定顺序，消费已有回调/显式协调，不用无序LateUpdate竞争。默认仅Gameplay Camera启用；SceneView、结构/侧看观察、UI明确旁路或标注诊断策略。

透明只改显示：Collider.enabled、碰撞层、NavMesh、既有Move、Attack/HitResolver、音声遮挡及世界状态不被修改。墙透明后仍按原规则挡路/挡弹；不得借机新增原来没有的攻击限制。

## 8. 样板与配置

新场复用草/路/花草、原双角色、单敌、35°及45°旋转/切控/zoom。包含普通厚墙合法前侧/侧边/后方路线、至少一个复杂高台与缓坡、前后双遮挡、小型可全淡出组及较大地形局部分组；不扩整张新地图。

参数在自有配置中暴露：目标/检测点/频率、核心与最大半径、羽化、开窗/恢复时间、退出滞回、整组许可/最低opacity、活跃组预算。包内0.12–0.20s开窗、0.20–0.35s恢复、0.08–0.15s滞回、最大半径2–3倍等仅为标定起点，不是已测最佳值。

当前后端硬上限2目标、4活跃组，配置必须拒绝maxGroups>4；检测起点为每目标约5点×20Hz。超额有明确诊断和主控优先级，不静默漏掉实际遮挡。minimumOpacity属于每个组，不放全局Settings；目标身体高宽用显式稳定范围，不从weapon bounds推导。提供中文登记/校验/配置/效果开关/诊断入口，不新增冲突快捷键，不自动重置用户地图。

## 已收敛的实施边界（2026-10-31）

这些是本轮明确接法及其继续验收的边界，不是整轮完成声明。

- 异常倾斜显示面切墙使用可选角色视觉深度适配：保留屏幕XY、原PMA颜色/alpha和Spine片层关系，按本角色脚点竖直平面求实际像素深度；不移动Root、抬脚或改物理。身体、左右独立Spine、实际Sprite装备分别取原图验证。合法前景高台遮挡必须继续存在。
- 官方`Spine/Skeleton`原颜色pass属于queue3000/PMA/ZWriteOff。前景装备即使alpha为1，也不能依赖其颜色pass写深度。`CharacterOpaqueCoverage`仅为明确源的近乎全不透明像素补自有深度覆盖，保持原色材质、顶点RGBA、纹理、透明队列和正常深度测试；开关作显式单变量对照，不能删掉失败的装备区域。当前默认近全不透明阈值为`.999`，半透明边缘不据此冒称完全覆盖。
- 有限后端捕获原Lit/已知cutout颜色及独立owned原始深度，各真实组按每像素深度处理；双圆取最大并集，伙伴支撑脚盘单独保留。目标是组内原实际可见表面正确合成，不能让多个地表层各自叠成灰膜。当前受控支持范围为明确Gameplay Camera、full viewport、URP renderScale=1、有限尺寸和已验证材质；未知变形、任意半透明材质、XR或未验Feature不得默默当已支持。
- 已知`GroundDecorationCutout`的Simple Sprite按真实SpriteRenderer结果适配：非白renderer tint与材质颜色、flip、SpriteID、两级TRS及有效MPB的纹理/颜色/裁剪都必须一致。原生Sprite的纹理注入与非空MPB优先级不能按普通Mesh想当然合并。同一Material对象原地修改颜色、cutoff或纹理时也要更新捕获色/深度，不能只比较Material引用或GeometryVersion。此项不推广为任意Sprite Shader/DrawMode已支持。
- 保存/刷图会替换顶盖Collider。平台组序列化原墙代理，由`QueryVolumes`读取当前`platform.capCollider`，不能钉住旧cap。装饰Sprite的查询Box属于独立`PhysicsScene`，不挂到原物件上，不进入主世界碰撞/攻击，不调用`Simulate`。
- 研究场的三份`GroundDecorationOrientation`明确绑定真实Gameplay Camera；私有Preview/foreign Game Camera不应使原装饰转向。该项在新Lab装配，不修改旧模块默认行为，仍须随新场保存、重开复验。
- 运行态驱动仅走公开Routes/Motor/镜头45度请求/原协调器，持有自己的输入capture lease，切控时先暂还再取得。状态只读；不直接推进Tick或造Demand，不写HP/alpha/时间。公开接口不足以精确归还已有路线会话或自定义zoom时先拒绝，不能覆盖另一写入者的现场。
- 死亡链专项可使用原`ApplyDevelopmentHit`开发受击入口产生真实Released→Health→Died，检查原Coordinator自动继任、死者资格/状态释放及伙伴历史延续；不能直接写HP、手调Current或调用SwitchNext代替自动继任。运行态死亡后不回填HP、不保存，以正常Stop返回初始。此项与敌挥击/Guard/LOS/复活验证分开。
- SceneView专项区分相机渲染与标签页GUI。可以在原有SceneView相机上用自有临时RT取得真实SRP回调，但须精确归还target/aspect/矩阵并销毁RT；不能新建Camera、改Actor或把manualRender写成真实标签页/硬件操作通过。未取得可归还的焦点时拒绝Focus，不猜原窗口。

M5–M7的动态站位、投影尺度、保存重开、三次Play、四态成本、连续画面和最终专项均以[validation.md](validation.md)中的实际回执及限定范围收口；私有小样和源码存在性不能代替这些门。尚未认证的长武器/坡脚、全场逐帧GPU颜色、任意材质/Feature、SceneView标签页GUI及实体硬件操作保留为边界，不写成全局通过。
