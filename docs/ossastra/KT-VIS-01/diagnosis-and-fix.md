# 截身原因与修复方案

## 两张反馈不是同一个问题

| 反馈 | 关闭环境透视后的实证 | 处理 |
| --- | --- | --- |
| 墙边切身 | 原角色胶囊没有碰墙，但倾斜的身体显示面进入墙体；正式网格绘制对照中，墙使 1,135 个原身体样本消失 | 在原角色表现链加入可选的脚点竖直深度适配，保持屏幕位置和颜色 |
| 高台前下身被遮 | 角色胶囊与正式身体网格均在平台外；墙没有造成该缺失，前景顶盖造成 1,950 个身体样本消失 | 保留原有前后关系，由登记环境模型局部透视解决 |

第一类修复必须在环境透视关闭时成立。正式生产适配的墙边复测为 1,698 个有效身体样本、0 个错误消失；不能靠把墙变透明替代这一检查。第二类在效果关闭时仍被高台挡住，符合正常深度遮挡。

## 角色显示深度

原 `CharacterRoot` 在装备和道具表现更新后，准备可选 `ICharacterVisualDepth`。Shader 根据实际主相机射线与角色脚点所在竖直平面求深度，保留原网格片层相对脚点的眼深度差。

这条路径不移动角色根、胶囊、骨骼或动画，不改变屏幕顶点、UV、颜色和人物透明度，也不使用 `ZTest Always`。只有样板中显式加装该模块的角色使用它，旧场没有组件时沿原路径运行。

实际 B 角色的身体、左右 Spine 装备及遗留 Sprite 装备需要共享同一契约。组合检查曾发现 Sprite 与身体交叠区域出现 192 个颜色差异；只读 `PresentedRenderer` 端口让 Sprite 取得一致深度，保留用户原装备脚本逻辑。

不透明装备像素使用自有的只写深度辅助绘制，原 PMA 颜色 pass 不改。曾出现的随机自遮挡来自辅助绘制把已单位化的法线再次单位化，造成一个浮点位差。修复为精确复制同一法线，不加深度偏移、不放宽像素容差。最终实际组合为 1,493 个有效样本、0 个颜色差异，禁用及重新启用同样为 0 差异。

## 环境模型透视

明确登记一件模型的墙、顶盖、封口及装饰。角色稳定身体点向实际相机查询未淡出的原 Collider；Sprite 装饰的检测 Box 位于模块自有 Physics3D Scene，不进入主世界攻击或碰撞查询。

遮挡程度驱动有界半径与强度，进入、扩大和恢复平滑过渡，退出保留短暂滞回。两个角色的需求取并集。大平台只开局部窗口；有限小模型才允许整件淡出。主控站台时保留整块承载顶盖，伙伴站台时保留脚盘，支撑冲突禁止整件淡出。

渲染后端捕获每个登记组最近表面的原颜色与真实深度，再按每个像素的远近合成柔边。它不逐块叠加半透明地表，也不把人物置顶。源 Renderer 只在指定主相机的绘制作用域内暂时隐藏；结束、异常、停用时按所有权归还。

装饰使用的 `DecorationCutout` 自定义 Shader 与普通 Sprite 不同。实测它不消费 Sprite 的颜色与 flip，但会消费原生绑定的 `_MainTex`。适配保持这些实际语义，不额外实现原 Shader 没有的效果。原生／用户 MPB 以及原地材质修改另有独立像素合同，不能仅凭“看起来差不多”签收。

## 关闭与适用范围

完全关闭时保留原图并停止遮挡、装饰代理和支撑检测；重新开启首帧按当前角色与镜头重测。检测模式保留原图，仅运行判定。

当前验证范围是样板的 URP/D3D11、标准透视和正交投影、明确主相机、已知不透明／裁切材质，以及无阴影、无 SSAO、无额外 RendererFeature 的配置。未知透明材质等不满足条件时保留原图。验证详情与未测项见 [validation.md](validation.md)，接入与配置见 [README.md](README.md)。
