# DS-MAP-01｜试玩与结构观察

这是独立地图研究样地：少量《饥荒》真实地表/场景物件，配合星骸现有角色、原输入/仲裁/动作/动画链。样地采用手工布局，展示相机旋转、人物换面、脚点与遮挡；不是原作存档、随机地图算法或流送系统的复刻。

本文按当前交互代码整理。具体已通过/未通过的实测，以本目录的验证记录为准；用户视觉与架构审查不由代码编译代签。

## 打开与运行

正式Unity工程：`E:/WORLDCREATOR/new/Project_ANKALUTE`。

场景：`Assets/OSSASTRA/Scenes/Research/SC_DontStarveMapLab.unity`。

在Edit状态打开菜单 **Tools → OSSASTRA → 地图研究 → 打开饥荒地图样地**，或在Project窗口双击该场景。菜单遇到未保存场景会停止，先处理自己的未保存内容；它不会替你保存其他场景。进入Play，点击Game视窗使其取得输入焦点。

本场只装配一个现有角色研究实例，来源是 `SC_CommerceIntegration` 的 `PlayerCharacter_BlueFiveFace` 与同名基础Prefab；研究Prefab入口为 `Assets/OSSASTRA/MapResearch/Prefabs/PlayerCharacter_MapView.prefab`。它不是此前的芙蕾茜娅单模型预览，也不会将两份场景一起运行。正式默认启动入口、基础角色配置和正式Q/E技能键不因研究场改变。

## 按键与按钮

| 操作 | 当前绑定 | 作用 |
|---|---|---|
| 人物移动 | 原角色的WASD、方向键、左摇杆 | 正常模式沿原控制链移动；相机旋转后仍按屏幕方向输入 |
| 人物攻击/技能 | 原角色绑定 | 继续走原动作与动画链；Q/E仍为原技能，实验镜头不占用 |
| 相机旋转 | 鼠标滚轮上/下；手柄十字键右/左 | 目标水平角分别+45°/-45°，平滑到位 |
| 拉近 | 按住PageUp | 有限缩小相机距离；结构模式缩小观察相机正交范围 |
| 拉远 | 按住PageDown | 有限增大相机距离/结构观察范围 |
| 恢复机位 | Home，或左上“恢复机位”按钮 | 正常模式恢复初始角度和缩放；结构模式仅恢复结构机位，不退出结构 |
| 正常/结构切换 | F6，或左上对应按钮 | 冻结正常显示基，切到独立结构相机；再次按下返回正常游玩 |
| 侧看纸片 | F7，或左上“F7 侧看” | 自动进入结构模式，从侧方低角度观察 |
| 俯视结构 | F8，或左上“F8 俯视” | 自动进入结构模式，从接近正上方观察 |

滚轮幅度120不代表旋转120档；同一次业务采样中的多个同向滚动合并成至多一档。要查看八个45°观察方向，请逐次滚动，待镜头到位后再滚下一次。十字键按下触发，长按不自动连转；相反方向同帧按下互相抵消。

滚轮不负责缩放。键盘方向键继续移动人物，未改成旋转键。所有实验Action都可在 `MapResearchRoot` 对象上的 **Map Research Camera Input** 组件检查和改绑定；不会写回角色共享InputLayout。

失焦会丢弃待处理镜头输入；若处于结构模式，也会退出该模式并释放自己的角色输入捕获。回到Game视窗后重新操作即可。左上说明面板属于UI区域；需要移动/瞄准时把指针移到场景中。

## 六步看懂这张地图

1. **先看正常画面。** 从出生空地向草、石头和树走近，观察人物脚底与地面。地图是XZ地面、Y向上；画面中的二维人物仍有独立的世界位置和碰撞。
2. **停住后转八个方向。** 逐次滚轮旋转，看同一棵树和人物的前后关系如何改变。变的是相机与显示方向，世界根、碰撞体和人物已确定的逻辑方向不应跟着绕原点转。左上显示实际角度与目标角度。
3. **沿物件前后绕行。** 从高树、低草、石头、箱子旁经过；再转镜头重复。高树冠不等于整棵树冠形状的碰撞体。样地边缘的灰蓝立方体/柱墙是自有3D混合遮挡诊断区，用来区分纯二维物件排序与真实3D遮挡。
4. **按F6或F7侧看。** 人物与物件的正常显示平面保持进入结构时的朝向，滚轮此时只旋转结构观察相机。侧看时纸片变薄甚至接近侧边消失是预期的结构展示；不是正常游玩时的Billboard故障。
5. **按F8看俯视与占地。** 观察网格、脚点、平面边框和碰撞。网格是4单位地形逻辑参考，物件的位置可以连续移动，不代表全部强制吸格。结构模式捕获新的角色输入，角色Root和一次性已受理的动作仍按原时钟运行；持续依赖Held的动作按下文手势规则处理。这不是游戏暂停，也没有设置TimeScale=0。
6. **按F6返回并再次操作。** 正常观察相机恢复控制，人物重新接受原输入。检查移动、原攻击和换面衔接；Home可恢复正常初始机位。退出Play不会把结构相机或临时显示状态保存回正式角色。

**持续按住动作的边界：**结构观察通过原有 `SetInventoryCapture(owner, true, true)` 捕获输入，不停住角色Root，也不伪造或保留新的Held输入。一次性已受理动作继续原时钟；盾防、蓄力等持续依赖Held的能力，按既有UI捕获手势规则结束。实测 `shield-a` 按住鼠标右键时 `Guard=true`，按F6进入结构后 `Guard=false`、`busy=false`，动作接受次数仍为1，没有重新受理或重播。退出结构后，需要先松开相应按键，再重新按下才能发起这类动作；不会因为之前一直按着而自动续上。这是保留原手势规则，本轮没有修改能力系统，也不是暂停功能。

## 结构标记与来源查询

结构模式的显示含义：

- 黄色十字/框：物件世界根脚点与登记占地。
- 青色边框：实际显示Mesh所在平面，不是另造的概念轮廓。
- 红色框：配置中的Collider世界包围盒。
- 红/绿/蓝轴：世界X/Y/Z；紫线：人物真实世界逻辑方向；白线：正常相机水平观察方向。

物件来源和参数通过Unity Inspector查看：在Hierarchy展开 **固定世界根_手工研究样地**，选中 `evergreen_tall_00` 等物件，在 **Scene Prop View** 中查看Source Archive、Source Entry、来源哈希、Evidence Level、Pixels Per Unit、Footprint、Snaps To Grid和Sheet Frames。`DisplayPlane` 是显示子节点，Collider在世界根上；不要移动DisplayPlane来代替移动物件根。

人物在结构面板中显示原角色诊断信息，包括世界方向/观察相对方向、换面和原动作/阶段身份。人物不是《饥荒》素材，不能把其角色SO或Spine字段解释成饥荒原作的结构。

## 拖入一个物件试摆放

现成模板目录：`Assets/OSSASTRA/MapResearch/LocalGenerated/Prefabs/`，例如 `PF_rock.prefab`、`PF_grass.prefab`、`PF_evergreen_tall.prefab`。它们包含本机受限媒体依赖。

1. 在Edit状态，把一个模板拖到本研究场的“固定世界根_手工研究样地”下，移动**物件根**的Transform，先让Y约为0.025；不要改整个世界根来转地图。
2. 选中新实例，将 **Scene Prop View → Stable Id** 改为本场唯一名称。位置不要求四单位吸附；Footprint只登记占地，实际阻挡由Collider决定。
3. 选中场景的 `MapResearchRoot`，把 **Props** 数组增加一项，将新实例的ScenePropView拖进去。若它有Collider，并且需要结构模式显示其碰撞，再加入 **Collision Volumes**。该模块由研究根显式调度，单独拖入但未登记的实例不会自动获得相机/动画更新。
4. 保存自己本次修改的研究场，再Play并转镜头检查。模型素材与基础Prefab不必修改；试验结束可撤销或只删除自己刚放的新实例。

ScenePropView的CameraPlane为正常相机平面，VerticalBillboard只绕竖轴，Fixed/Ground保留作者设置。当前选定物件依据源默认Billboard配置为CameraPlane；其他模式属于诊断/适配选择，不意味着原作每个物件都用了同一矩阵。

“首次生成”命令会拒绝覆盖已有场景、Prefab或不同内容的贴图。没有一键抹掉用户修改的“恢复整图”命令；需要重新生成时先保留自己的研究场副本，并按任务范围处理生成目标，不能删除其他场景来解锁。

## 如何理解验证结论

- **SOURCE_VERIFIED**：本机所选单机版本的相机参数、45°旋转符号、逻辑格4、连续物件坐标、默认Billboard以及素材/碰撞来源，有路径与SHA-256可核对。
- **UNITY_ADAPTATION**：手工样地、PPU100、按图像角点alpha选边、Unity材质/深度策略、现有角色视角适配和结构相机，是本轮等效实现；不称为原生算法复制。
- **OBSERVATION_BLOCKED / UNKNOWN**：原作两次启动没有可控窗口，八角度原作对照未完成；确切原生投影/Billboard矩阵、自动选边与noise周期仍未知。Unity可玩并不能消除这些未知。

实际PNG合成检查和119项转换合同已通过；Unity正常移动/攻击、换面、遮挡、结构切换、生命周期和重开结果，请查看本轮单独验证记录。用户仍可根据真实画面审查这套方案是否适合正式地图。

打开菜单现会预检40张贴图、9个本机物件Prefab和10个Mesh；缺失时列出精确路径并保留当前场景。公开壳的GUID必须与配套本机资源和.meta匹配，导入图片或“首次生成”不会自动修复已有壳。预检10项合同通过，未删除素材来制造缺失。
