# DS-MAP-02｜双角色战斗样地试玩指南

本轮入口是 `Assets/OSSASTRA/Scenes/Research/SC_DontStarvePartyCombatLab.unity`。场内保留上轮三种地表、40个物件，使用现有小蓝A、完整战斗角色B和一个原敌人；没有使用尚缺战斗动作的芙蕾茜娅预览替代B。

## 打开与操作

退出Play并保留当前未保存工作，再使用菜单 **Tools → OSSASTRA → 地图研究 → 打开双角色战斗样地**。进入Play后点击Game View空白处取得输入焦点。

以下绑定已按本轮保存场景核对；如后续在Inspector修改，以实际InputAction为准。

| 操作 | 当前绑定与行为 |
|---|---|
| 移动 | WASD／键盘方向键／手柄左摇杆，沿当前画面方向移动 |
| 普攻 | 鼠标左键／手柄RT；连段沿既有动作库和点击规则衔接 |
| 切换角色 | **Z／手柄Select**，由原协调者切换唯一主控 |
| 镜头旋转 | 鼠标滚轮／手柄十字键左右，每次有效请求45°；滚轮幅度不等于累计档数 |
| 放大、缩小 | PageUp、PageDown；滚轮用于旋转 |
| 恢复机位 | Home，恢复当前正常／结构观察模式的机位；不恢复人物HP |
| 技能 | Q／E保留原技能绑定，不用作镜头旋转 |
| 结构观察 | F6进入／退出；也可点击左上“查看纸片结构／返回正常游玩” |
| 侧看、俯视 | F7、F8，直接进入相应结构观察视角 |

镜头角度和缩放属于同一个场景会话。A切到B时，当前旋转及尚未完成的45°过渡继续，镜头中心平滑追向新主控；不会为迎合人物朝向而自动转180°。两人的视觉持续使用同一观察基，各自保留世界朝向和动作状态。正常镜头围绕目标旋转，地面、人物逻辑根、物件根和碰撞不跟着旋转。

非主控使用原伙伴跟随／自治战斗链。主控死亡后由原协调者交接存活者；全灭时没有合法Current，镜头保持最后合法中心，不自动复活。

## 结构观察不是暂停

F6冻结正常镜头与显示观察基，改由另一台相机侧看／俯视二维平面。观察期间滚轮只转结构相机；F6退出后恢复正常游玩视角。

此时玩家移动、攻击和手动切控被捕获，世界时钟仍继续。已受理动作、伙伴与敌人仍可能行动，角色也可能受伤或死亡。左上结构线用于核对显示平面、脚点／占地和碰撞包围框，不代表完整美术或导航系统。

## HP与遭遇复位

底部遭遇面板显示A、B和敌人的实际HP，并显示当前切人绑定。点击 **重置本次遭遇**，显式恢复本场实体的出生位置、角色生命／体力与敌人，取消旧角色动作并重新选择合法主控；镜头角度和缩放保留。敌人不会在死亡后无限自动返场。

本轮战斗故事验证35/35通过，覆盖原攻击释放与命中、伙伴真实击杀、敌人击杀A后交接B、全灭Current为空以及显式复位。这是技术验证范围，实体手柄手感与用户完整试玩仍单独确认。

## 遇到局部闪烁时记录

闪烁诊断默认关闭。底部诊断面板和 `MapResearchRoot` 上的 `MapFlickerTraceRecorder` Inspector提供相同入口：

1. 点击 **开始追踪**，再尝试引发异常。
2. 看见异常后及时点击 **标记异常并导出**；它只标记／导出，不暂停世界。Inspector也可“仅标记当前异常”，稍后再手动导出，以留下后续样本。
3. 点击 **停止追踪**保留本轮记录，停止正式事件采样。重新开始会建立新一轮环形记录并清除旧标记。

默认保留最新2048条样本，超出后覆盖最旧样本；这不是固定秒数，帧率、身体数量与渲染阶段都会影响可追溯时长。采样不自动写盘，仅显式导出时生成JSON。默认目录为 `Application.persistentDataPath/OSSASTRA/MapResearchDiagnostics`；面板会显示实际文件路径，Inspector可选择本机文件夹。

记录包含原控制会话Current／ControlRevision、实际观察角、方向面／镜像、动作／轨道、正式网格摘要，以及相机阶段和各自帧号。相机阶段可能沿用较早生成的mesh，应结合 `meshFrame` 和 `slotPoseFrame` 判断。它不自动录制画面；局部身体／装备异常还需可定位的录屏或相邻画面证据。CPU摘要正常不能证明GPU画面始终正常。

## 本轮闪烁修复的准确范围

已在真实小蓝固定姿态的GPU对照中确认研究材质下的共面层深度不稳定：原配置仅有极小相机角变化，身体内部就出现条纹与层片串露。研究专用 `MapResearchSpineDepth` 使用极小片层间距，并在正式生成网格后按实际顶点重算bounds；保留原Shader的深度写入、深度测试与透明边界。

修复后同轨迹GPU快照的内部高差像素为0，实际bounds已为正。此结论覆盖已确认的研究共面缺陷；**用户报告的全部局部身体与独立装备动态闪烁尚未逐一关联，不能据此宣称所有闪烁都已关闭。**

## 保存、重建与资源边界

- 旧 `SC_DontStarveMapLab.unity` 保存内容保持不变。旧单人样地通过其研究专用 `PlayerCharacter_MapView` 变体获得深度策略；基础Blue预制体及原Commerce、Freycia场景不修改。
- 菜单 **3 首次生成双角色战斗样地**用于首次装配，复用已保存MapLab和Commerce实际角色配置，不覆盖现有成品，不重新提取媒体。新装配也会包含默认关闭的诊断组件和研究深度策略。
- 地图原图、原作代码、派生帧表／Mesh／物件Prefab及带媒体的截图／录像仅留本机，不随公开仓库发布。缺少本机依赖时菜单会保留当前场景并提示；资源与 `.meta`／GUID应配套恢复，重新导入PNG或再次首次生成不能自动修复已有场景壳的GUID引用。
- 本轮不安排关机或休眠动作。
