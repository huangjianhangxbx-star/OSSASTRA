# SV-RENDER-ACE-02 接缝与方向边光融合

正式横版场 `Assets/OSSASTRA/SideView/SC_SideViewAdventure.unity` 延续 ACE-01，在 C ACELight 内提供融合、基础和旧材质三个入口。保存重开后默认展示融合。A Legacy 和 B Silksong 仍可切换。正式场和参考素材按原有本机交付范围保存。

## 接缝和颜色

- 正式场固定机位核实小蓝 `BlueFiveFace` 是直通 Alpha，而四种基准策略实际都使用 `_SideViewCutout=0`、`_PmaInput=0`、`_STRAIGHT_ALPHA_INPUT=false`。该图集的半透明 RGB 进入 PMA 混合时缺少乘 Alpha 的步骤。
- ACE 变体按实际图集身份修复关键字，原图集文件和导入设置保留。图集匹配在源属性同步时重新判断。普通槽处理覆盖，单独的原生混合槽仍按自身 Blend 工作。A/B 与 C 旧材质参考保留基准外观。
- 同姿态 1600×900 下，发片异常亮点与邻点的显示亮度差由 60.01 降到 0.43。融合的内外边光均关闭时，同一处仍已修复。黑色线稿与代表性不透明发色保留。白光与原图直通的整帧截图逐像素相同。
- ACE 场景画片的贴图与作者顶点色改为在作者 Gamma 域合成，覆盖 Alpha 保留。B 自有调色曲线、饱和度与 Bloom，以及各自的底光、灯位和角色染色会共同造成 B/C 艳度差。此次保留 C 作者灯参数和 B 调色。

## 角色融合与照明

- C 融合以同相机 ACE 角色 Ambient 着色，以有符号光向及线性局部灯能量驱动完整轮廓的内边光和外缘柔光。方向图按最终相机像素约定处理纵向。双灯相反时方向相互抵消，灯灭后局部边光退场，环境底光继续负责角色主体的暗部可读性。
- 两角色复用现有独立联合 Alpha 轮廓和外缘显示器，沿用前景顺序及不透明深度。默认内边宽 2.5、外缘宽 3.8 个 1080p 参考像素。运行时的“光图调试”分别控制内边光、外柔光和中性消融，还可查看双角色覆盖及带符号的灯光方向与权重。
- C 基础与融合只依赖 ACE 资源及角色表现配置。实机暂时撤下旧照明引用，基础与融合均可选，选旧参考时明确报告缺项，恢复引用后旧参考可以进入。
- C 切换同一灯光、同一角色站位的基础和融合时，场景画片采样保持一致。起始笼暖光、东侧冷光和暗区均有对照。

## 正式 Play 验证

- 同相机光图读回 15/15。左、右、上、镜像、旋转加非等比、对向叠加、弱光、关灯通过。上灯 Y 在 1600×900 为 −0.3997，1384×663 和 Render Scale 0.65 时分别为 −0.3977 和 −0.3972。窗口、比例和项目配置已归还。
- 基础 8 张 ACE 图，融合 10 张，切到 A 后 ACE 图释放，再回融合恢复 10 张。800×450 的两张 RGBAHalf 与 1024×512 RGBA8 联合轮廓新增约 7.49 MiB。完成两次五策略往返后，融合依然是 2 个外缘材质、6 个 ACE 角色变体及 1 个覆盖材质。两角色仍使用独立格；原默认副手无有效 Lhand，另在 Play 临时登记项目已有 Sprite 检查独立装备，轮廓提交从 2 到 3，随后归还。主场未保存该测试道具。
- 正常左右移动和转身、J 起跳、木桩真命中、实际受击特效与震屏、同台连续回抓和两次翻越、近距离真实 Z 键交换主控均录到。回抓录像期间有 622 个融合渲染帧，缺当前帧光图 0。双方紧邻仍通过物理排除和主控前置。定向用临时不透明遮挡体检查柔光深度，连同实录中的前景和平台观察。
- 同机位 RTX 4080 SUPER、D3D11 Editor、1600×900、4×MSAA、Render Scale 1，基础／融合／基础返回各 360 帧。GPU 整帧 P50 为 1.905／1.923／2.021 ms，CPU 主线程 P50 为 3.007／3.062／2.952 ms，渲染线程为 1.427／1.422／1.404 ms。每帧提交 292／300／292，新增 4 次方向光图绘制与 2 次轮廓绘制，其余为两角色外缘。融合 GC 中位数较基础多 754 B/帧，分阶段 GPU 时间不可用。整帧 GPU 差异落在基线往返波动内。
- 项目正常 Gameplay Listener 实录含场景音、动作和命中，MP4 1600×900，48 kHz 双声道。临时采样脚本移出 Assets 后，再次保存场景重开并进入 Play，融合、按钮、材质引用、两角色覆盖和唯一 Gameplay Listener 均读回。
