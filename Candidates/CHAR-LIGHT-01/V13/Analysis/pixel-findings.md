## 方法与范围

先查看原始 1600×900 PNG，再固定小块角色内部 ROI。通过 System.Drawing LockBits 只读字节比较，不对包含大量地面的角色大矩形计算“细节”。以下 Y 是 **8 位已编码 RGB 的加权值**（0.2126R+0.7152G+0.0722B），不是线性亮度、HDR 或 GPU 增益。近白表示 RGB 三通道均 ≥250，仅用于描述显示结果；它不是验收阈值，也不证明丢层次最早发生在哪个渲染阶段。

## 非角色区域

正午排除两角色连同外晕的松包围并集：Freycia (781,302,98,159)、Blue (724,374,99,132)，剩余 1,415,004 像素。A2 对 A1 的平均 RGB 字节绝对差 0.077234，变化像素 0.16177%。light/medium 对 A1 的相应值为 0.092406/0.086870，变化像素 0.18629%/0.17640%，与 A/A 同一数量级；strong 0.001833、0.03145%。各组 P99 最大通道差均为零，但少量动态像素可有较大差异，故不使用全图最大差判世界颜色回归，也不虚设一个“白色小于1%”通行标准。

五环境在另外的角色松包围外，平均 RGB 差 0～0.033622，变化像素 0～0.07021%。它们没有各自 A/A 复拍，正午 A/A 只能作为上下文，不能当作其已校准噪声。室内外动态、UI 和粒子也可能变化。本统计没有显示广泛全场变色，但不代替实际渲染绑定与画面检查。

## 输出与复现

- `AnalyzeImages.ps1`：只读 PNG，复算正午八张与存在的五组 A/B，并核对输入运行前后哈希。
- `noon-pixel-analysis.json` / `environment-pixel-analysis.json`：完整 ROI、分位、相邻差与区域外差异。
- `summary.json`：本次较小快照；重拍或改 ROI 后应以脚本新产出的完整 JSON 为准，并同步更新本报告/摘要。
- `input-integrity.json`：18 张输入在完整运行前后没有改变。

结论限于：light 对最白内部区域不足；medium 显示端保留余量而强档进一步压暗；暮色/夜间所采内部不变；室内局部灯确实也受总保护校准影响。是否采用 medium、是否需走局部主光备用路线，由完整现场及 GPU 读数和 Root 的画面对比共同决定。本报告不授予审美 PASS。
