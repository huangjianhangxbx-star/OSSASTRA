# 原创音声替换指引

本轮建立的是现有玩法事实到统一音频根的内容接线。当前本机 A3 使用血源参考候选，人工听审尚未完成；后续换成原创音声应主要替换内容与作者配置，保留动作、伤害、控制、库存及音频根的职责边界。

## 保持哪些接口稳定

- 稳定语义：`selector / kind / stage / channel / deliveryMode / role / material`，以及映射得到的 cue 和最终 event ID。它们描述真实动作/投递/身份，不写入具体录音文件名或动画名。
- 角色身份保持 `player / companion / enemy`，具体声音可共用或分配不同变体；不能为换素材改变 `CharacterRoot`、敌方根、控制权或招式归属。
- 真实事实身份保持来源租约、世界代次、执行 ID、子击/EmissionIndex、TargetId 与单次键。同技能的多目标和合法后续子击不能被粗暴合并；旧世界排队声不能换新租约重放。
- 唯一 `GameAudioRoot`、BGM 仲裁与 transport、SFX 仲裁/固定声源池、统一 Mixer 继续拥有实际播放。不把 Lab 的 Director、第二个播放器/DDOL 根或另一套伤害时钟搬入正式角色。

`SEMANTIC_COVERAGE.csv` 保留所有旧 72 条绑定和本轮新增条件；它是复核入口，不是媒体数量统计。`BB_SOURCE_MAP.csv` 单独保存当前参考源、派生哈希与出处，替换原创后保留这份历史证据。

## 用原创内容替换的顺序

1. 将有权用于项目的原创 PCM 和作者说明放在明确的原创音声目录，保留源版本、作者/授权、用途和原始哈希。不要覆盖或改名原血源提取库、Lab 或旧音声目录。
2. 建立原创内容 SO 及对应 catalog。沿用已存在且意义仍正确的 event ID，把 `clips[]` 改为原创片；不要通过在玩法代码写死某个 wav/动画名来替换。需要新语义时先说明真实事实出口，再添加映射。
3. 使用 Unity Editor API/MCP 创建或修改 `.asset`、`.prefab`、`.unity`、`.mixer` 和导入器，不用 YAML 文本替换 native 资产。当前私有 `ReferenceSemanticProfile.asset`、A1/A2/A3 catalog/profile、引用私有媒体的曲目/规则 SO 均留在 Git 排除区。
4. 原创音声目录、SO 和默认档案属于新交付时单独决定的发布范围。只有媒体授权和依赖链完整时，才把原创 PCM 及引用它的 native 资产纳入公开仓库/Player；不能把原血源目录仅改名后发布，也不能让公共 native 资产隐含引用私有 GUID。
5. 先替换四段普攻、真实接触/格挡、枪械装填/落地爆炸、闪避/治疗及角色/敌人受伤；再处理冰系、金属脚步、食物、环境、音乐。表中的近似项是优先替换目标，保留其状态直到真正听审通过。

## 内容作者需要填清的内容

| 层面 | 需要的配置/说明 | 保持的边界 |
|---|---|---|
| 单次 SFX | event ID、真实语义、变体、音量、pitch 范围、优先级、同来源上限/间隔、bus、空间距离 | 间隔仅为内容策略；不吞掉合法独立子击，不再做一次命中判定 |
| 连段 | 四段各自的释放录音与阶段映射；接触按真实目标材质 | 四个 event 不应只是同一录音改 pitch 后声称有四份素材；释放与命中分开 |
| 动作/技能 | release/launch、实际 hit/miss、channel、deliveryMode；哪些通知保持静默 | 枪响不能当装填，launch 不能当爆炸，空挥不播接触；空落的合法爆炸仍可发声 |
| 接触材质 | flesh/metal/stone/wood 的独立录音与目标标记 | 仅明确 `AudioSurfaceFact.impactMaterial` 可提供材质；未知不猜 |
| 角色与敌声 | 适用身份、攻击/受伤/死亡、变体、呼吸/人声占用说明 | 匿名 c1050 声线不代表正式敌人设计；共用媒体不改变来源身份 |
| 脚步 | 地表、走/跑、变体、接触节奏；泛用/近似策略 | 根据碰撞后实际位移，不根据按键；当前 metal 使用石、wood.run 使用 walk 的近似需替换 |
| 消耗品 | 物件使用音与能力效果音的分工；具体食物/药品身份 | 消费提交和恢复 release 不能无条件双响；失败事务不播成功声 |
| 环境 | 真实源位置、区域、范围、淡入淡出、loop 起止、遮挡/混响配置 | Loop/区域放置是本作编排；停止只释放本来源，不停整个根或其他环境 |
| BGM | 内容 ID/版本、section、媒体身份、已验证 loop 点、确知 BPM/拍号、业务 context | 同内容保持连续；未知 BPM 留未知，不根据音频时长臆造节拍或原曲职责 |

本轮三份音乐的 SO 为 `whole_candidate_loop`、`knownBpm=0`，当前整段循环仅是候选配置。MusicBox、Ludwig01、Clock01 的正式角色、可用接缝和原四声道意义尚未确定。原创替换要明确内容/section/asset 身份更新，既避免旧解码仍被当成同内容，也避免同曲只因场景重开便重播；继续交给现有 transport 处理切换。

## 替换后如何验证

- 先查依赖与来源：catalog 中每个媒体存在、哈希/导入正确、参考私有资产不被公开场景或构建引用；缺少本地参考时应显示明确不可用，不静默谎称新档案已经覆盖。
- 在原玩法中实际输入：合法装备/释放、空挥四连段、命中/格挡、装填、落点、治疗成功与拒绝、切控、死亡与来源重建。不要用直接发声按钮替代完整接线验证。
- 验证走路/顶墙/停止、区域进出、同场切档、换场与反复重开：只有一个音频根/监听器，声源池保持有界，循环与旧队列不泄漏。
- 同条件比较 A0/A1/A2/A3 或原创候选档，匹配电平并保存事件/来源 trace 和真实 Listener/Mixer 输出。母线静音测试验证实际输出，不仅检查字段数值。
- 最后按 `CANDIDATE_LISTENING_QUEUE.md` 人工判断同步、力度、层次、身份和空间。通过测试、请求接纳、`SourcePlayIssued`、素材齐备与无削波分别只是技术事实，不能代签听感。

初次真实故事的 237 条事实/153 条音频观察、70 秒 peak 0.228223965/clip 0、声部峰 8，以及旧故事 **20/21** 原样保留为该次候选证据；未观察到的短敌击窗口与冰/金属脚步/食物身份等限制不因原创文件数量增加而自动消失。后续新增验证应另记版本与结果，不覆盖历史失败/未观察记录。

敌方 alert、尚未接类型化成功事实的库存操作、正式标题/剧情 Host 等属于玩法或适配缺口。换音频本身不实现这些功能；需要真实出口后再按相同语义链补齐。

## 本轮公开发布边界复核

收尾静态检查时，`Candidates/AUDIO-BB-FUSION` 包含 88 份文本文件（CSV/JSON/Markdown/JavaScript/C# recipe 文本），没有音频媒体扩展、Unity native 资产或 RIFF/OggS/FLAC/ID3/FSB 音频文件头，也未发现 `data:audio` 或 base64 媒体嵌入。公开的媒体来源表、哈希、电平、事件/声部 trace 和制作 recipe 属于元数据/工具，不包含参考 PCM 或派生音轨。

`.gitignore` 最后明确排除 `Assets/OSSASTRA/Audio/BloodborneLocal/` 与文件夹 meta、`CuratedLocal/` 与 meta、旧 `Art/AudioReferenceLocal/`，并排除本 Candidates 下的 WAV/OGG。当前未发现其他音频格式；后续仍应按精确文件清单发布，不能因为 Candidates 目录已放行，就把 MP3/FLAC/FSB 或改扩展名的音频放入其中。

公共 `SC_AUDIO_BB_Fusion.unity` 可保留公开脚本和继承的原场景资产依赖；本轮只读抽取的 346 个私有媒体/私有 SO 依赖 GUID，与新场景 144 个唯一 GUID 没有交集。私有档案由本机内容入口加载，不能把它们的 native 引用写回公共场景/预制体。这是文本静态筛查，不能替代 Unity AssetDatabase 完整依赖检查或 Player 构建证明；本轮也没有据此声称公共干净克隆已具备全部本机第三方角色/参考媒体。

源码与 recipe 中出现私有路径名称，是为了本机作者流程，不代表该 native 资产或媒体获准公开。原始库和派生 WAV、实际 Mixer 录音、归一化盲听副本继续留在外部工作目录或被排除的本地内容目录。替换原创后仍需重新检查授权、依赖和构建，不能继承参考内容的本机可用状态作为发布许可。

验收口径保持分离：初轮操作证据为 20/21；A/B 是同一真实事实的引擎回放比较，声部峰 5/5/9/9，原始输出均无削波。两者不代签人工听审，也不消除冰系、金属脚步、食物身份及未实现玩法入口的缺口。
