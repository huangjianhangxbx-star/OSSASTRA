# 私有候选：统一水平平面片元深度

这是对照代码，不是生产修复或已通过回执。正式 `GroundThinTop.shader` 不变；Shader由root通过 `ShaderUtil.CreateShaderAsset` 仅创建为非persistent对象。

先测 **LayerStep=0**。所有共面层在同一屏幕像素、相同nointerpolation平面高度下计算相同 `SV_Depth`，保留原队列及正常 `ZTest LEqual`。仅第二轮再测 `0.0005m` 的view深度步长，不预设最终需要虚拟层分离。现有root回执中名义24位RT实际为 `D32_SFloat_S8_UInt`，不把它改称D24测试。

## 接入同一个opaque oracle

1. Root执行 `CreateUnifiedPlaneCandidate.cs.txt` 中唯一IFunplay入口 `KT03Fix01CreateUnifiedPlaneShader`，读回Shader实例ID、非persistent状态、源码SHA和编译错误。默认step为0。
2. 原oracle继续只复制生产Mesh/Material到独立PreviewScene，不改生产Renderer。**将旧 `RenderHeightStep` 置0**，保持相机、mask、底纹、UV、颜色、Single0/Single1/Pair和5×5样本判定全部不变。
3. 在原 `renderer.SetPropertyBlock(block)` 前，调用已加载helper：

   ```csharp
   KT03Fix01UnifiedPlaneCandidate.ApplyToSnapshot(material, block, chunk.layerIndex, 0f);
   ```

   若oracle是另一次动态编译，按类型名从已加载程序集反射该静态方法。第二轮仅把最后参数换成 `.0005f`。helper拒绝persistent及非HideAndDontSave材质，保留完整原属性/MPB/队列，只替换私有Shader并设置新的HLSL米制参数。旧 `_DepthUnits`/`_DepthFactor`保留兼容字段，但Shader明确 `Offset 0,0`。
4. 按原方法等待Renderer注册、执行所有姿态、读实际depthStencilFormat及opaque oracle结果。Shader创建成功不等于图像通过。
5. 私有场景/Material清理后执行独立 `ReleaseUnifiedPlaneCandidate.cs.txt`；只删除登记的同名非persistent Shader。

## 深度路径

顶点阶段的 `planeYWS` 使用 `nointerpolation`；不使用片元插值的 `world.y` 建平面。原顶点XY和颜色插值不改。片元通过像素坐标除以 `_ScaledScreenParams.xy` 得到官方重建示例使用的UV，再由逆VP构造near点和far齐次点：

`D = farWorldH.xyz - nearWorld * farWorldH.w`

`P = nearWorld + D * ((planeY - nearWorld.y) / D.y)`

齐次方向不需要先除far的w，避免无穷远方向除零。随后强设 `P.y=planeY`，转view space，仅对最终写入深度使用米制偏移，再经实际投影矩阵得到设备深度。原 `SV_POSITION.xy`、world-XZ底纹、Sprite UV、颜色及alpha clip逐行保留。该候选不采相机深度纹理、不清深度、不后置覆盖角色。

near/far值采用本机API宏；反向深度直接输出投影z/w，正常深度根据 `UNITY_NEAR_CLIP_VALUE` 将可能的GL范围映射至[0,1]。偏移限制在相机near/far内。近平面及几乎平行射线有显式门，不用原primitive插值深度作静默回退。

适用本轮已验证水平共面平台、非XR、全视口Preview RT。当前代码具备正交/透视的两点射线形式，但未经Native结果不能宣称两种投影、动态分辨率、部分视口或其他图形API都已通过。需另外验证正常角色/侧壁遮挡；opaque层序oracle本身不充分证明绝对深度正确。

## 成本及判定边界

每个通过alpha clip的片元新增逆VP射线、平面交点和投影运算，并写 `SV_Depth`。Unity明确该输出在不少GPU上会关闭部分深度优化；不可预言它更快。[Unity 2022.3 shader semantics](https://docs.unity3d.com/2022.3/Documentation/Manual/SL-ShaderSemantics.html)

没有强制earlydepthstencil，也不声明保守深度语义，因为重建值与原三角插值值之间可能有双向舍入差。MSAA以及所有非discard路径正确写深度亦需按实际目标验证。[Microsoft HLSL semantics](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/dx-graphics-hlsl-semantics)

最终是否采用取决于同一oracle、实际遮挡和有界性能对照；本候选不替代root正在做的大units/微小显示层分离/显式D24等单因素实验。

## 生产接入只读复核（2026-10-30）

Root已报告候选step0的最小层序样本37996/0、实际多层A 72005/0、B 97281/0。它们是相应oracle的真实回执，尚不能单独代表所有opaque绝对遮挡、MSAA、正交或GPU性能均已验证。本段不改写原始候选的适用范围。

建议生产最小改动为同名、同GUID的 `GroundThinTop.shader` 内部替换：保留原颜色/UV/mask、AlphaTest队列、LEqual、ZWrite及原顶点几何，固定 `Offset 0,0` 和统一平面深度；若step0后续对照均通过，生产不引入实验性的米制层步长配置。生产实际代码仍需再走同一oracle，不能用候选结果代替。

兼容旧持久材质时，`_DepthFactor`、`_DepthUnits`可隐藏并标注“旧字段，渲染已不使用”，保留属性名。Authoring第149/157行仍写入0/-layer、Persistence第134/151行仍复制并参与签名，Shader固定Offset后这些旧数值无视觉效力；本轮可原样保留，避免只为清无效字段改写材质或签名。不要单独移除Shader属性却留下这些GetFloat调用，也不需要重建/迁移已保存的Material资产。

绝对遮挡方面，step0没有有意把顶盖推近相机；写入的是该像素射线与真实水平面相交的投影深度，平台高度不同仍得到不同深度。与普通opaque的硬件插值深度比较仍可能有浮点舍入差，因此不能保证严格共面的外部opaque胜负。最小回归应包括同一像素上方/下方有明确间距的opaque遮挡板，以及本图实际角色、侧壁/坡道与顶沿接触；绝不能因层序归零改成Always或清深度。

near/far沿实际GPU投影处理；候选先按真实view深度裁剪再输出设备深度，没有把越过近平面/远平面的点推回可见区域。边界只在浮点范围内成立；若相机裁剪面恰好穿过地面，还需实际画面验证，而非把saturate当作裁剪正确性的证明。反向Z的投影约定依据[Unity 2022.3平台差异](https://docs.unity3d.com/2022.3/Documentation/Manual/SL-PlatformDifferences.html)。

正交投影的near/far两点为平行射线，现有逆VP→平面交点→实际投影形式在数学上适用，并未使用只适合透视的线性化深度公式；这属于代码推导，仍需Native正交读图后才能写“正交通过”。XR、部分视口、斜面不扩入本轮。

MSAA是明确技术边界：当前片元以像素中心求一个深度，该值用于覆盖到的samples；其他普通opaque可在子采样位置有不同的硬件深度。因此AA=1通过不等于AA>1通过，几何边缘/相交处可能损失MSAA的深度分辨能力。Microsoft直接记录了该限制：[HLSL SV_Depth限制](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/dx-graphics-hlsl-semantics)；默认MSAA的像素着色/逐sample深度行为见[Rasterization Rules](https://learn.microsoft.com/en-us/windows/win32/direct3d11/d3d10-graphics-programming-guide-rasterizer-stage-rules)。不能仅凭QualitySettings的antiAliasing推定当前URP/RT的实际samples，应记录Native目标值。本轮不新增sample-frequency渲染方案。

性能结论限于成本已增加：额外逆VP求交与重投影按通过alpha裁切的屏幕像素执行，风险随覆盖像素和叠层增长，不随少量三角形数量简单推定。普通SV_Depth可能抑制early-Z；不可强加earlydepthstencil或保守深度语义，因为重建值与硬件值的差值并无单向保证。已有Editor CPU耗时只能说明CPU口径，不能替代GPU计时；在同RT/分辨率/层数下的有界前后渲染耗时只能作为该机器该场景的比较，不宜宣布跨设备性能结论。[Unity深度输出成本说明](https://docs.unity3d.com/2022.3/Documentation/Manual/SL-ShaderSemantics.html)
