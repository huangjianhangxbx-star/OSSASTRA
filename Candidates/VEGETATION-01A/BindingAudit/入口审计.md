基准：本机 `23e50dd5f351e5c71bf7385eadf7379f9554b980` 后工作树，2026-11-09。子任务只读生产代码；未操作 Unity、未改共享源码、资产或 Git。下文是源码审计，不是实机通过证明。

## 首要结论

**当前没有“保留自定义草 Shader 并进入正式 Room 许可合成”的已有公开扩展口。** 自定义 Grass Shader 可以用于没有 Room 接管的独立 URP 小场，消费既有同相机环境并验证颜色/深度/阴影；但不能将其直接登记为主场 Room 表面后宣称门窗、黑幕与许可已兼容。本轮若坚持不改共享后端，交付应停在独立候选，明确标记 Room 集成与主场回接未通过，而不是用另一条 Graphics 绘制覆盖黑幕。

路径前缀：`Assets/OSSASTRA/Scripts/SceneVisibility/Rooms/Rendering/`。

## 可安全复用的环境来源

命名空间 `Ossastra.EnvironmentSimulation`：

```csharp
EnvironmentCameraRegistry.TryGet(Camera camera, out EnvironmentFrame frame)
EnvironmentCameraRegistry.Published // Action<Camera>
EnvironmentCameraRegistry.Released  // Action<int>, camera instance ID
```

`Runtime/EnvironmentFrame.cs` 是不可变快照，草只读取 `Enabled`、`Seconds`（double）、`WindDirection`（Vector2）、`WindSpeed`（float）。适配器持明确 EnvironmentRoot 与 camera；必须核对同场、相机就是 `environment.gameplayCamera` 且登记有效。Published只处理自身相机；Released、禁用和销毁要取消提交/恢复自有状态。可选消费者异常由Registry隔离，但不能依赖吞异常继续渲染半初始化状态。

`EnvironmentRoot.Update` 推进现有时间，`Advance` 在 `:120` 将 Seconds 限制为86400秒周期。不要由草再调用 Advance 或创建第二套计时器。风频率不要直接用累计Seconds乘突变WindSpeed；强度可控制有界摆幅，传播相位固定时间尺度。若要跨86400回绕也严格连续，波函数周期应与该周期相容，或显式保留无跳相处理。

`WeatherProfileSO.windSpeed` 非负，缺省 `.35`；没有声明 m/s 单位或1的硬上限。实际帧风速 = Weather风速 × EnvironmentRoot.windMultiplier × Climate.windMultiplier（`EnvironmentRoot.cs:215`）。旧CPU叶片里的 saturate/15度仅是那个旧消费者的本地选择，不是环境权威范围。

## 普通颜色受光复用

`Ossastra.EnvironmentSimulation.Rendering.EnvironmentSkyBinding` 在 `beginCameraRendering` 为本相机调用 `UploadOrdinaryForCamera(cmd,camera)`，End仅归还owned相机的环境全局。别的有效Binding已拥有相机时不会清掉它的上下文。当前活动Scene与有效环境登记是硬条件（`:89`）；独立Lab需自己的有效环境接收者和明确灯引用，不能只拿一个新camera期望主场Binding照顾它。

草颜色可复用：

```hlsl
#include "Assets/OSSASTRA/Scripts/EnvironmentSimulation/Rendering/EnvironmentLighting.hlsl"
// role 0=地面、1=场景装饰、2=角色。草使用装饰1，不调用角色专属轮廓保护。
color.rgb = EnvironmentShade(color.rgb, worldPosition, normalWS, 1);
```

注意 `UploadOrdinaryForCamera` 不供应每个表面的 `_EnvironmentResponseOverride`、`_EnvironmentReceiveShadow`、`_EnvironmentMinimumOverride`。现有 Room 通过 MPB/逐draw提供；独立草必须在**自有材质/自有属性范围**明确供应正常值1/1/0并GPU核实。不要全局 SetFloat 补洞污染其它表面，也不要把 include 成功当作受光通过。若采用MPB，记录其实际批处理成本，不能凭勾选Instancing宣称SRP Batcher与实例化同时生效。

EnvironmentShade使用已登记局部点灯工作集（最多8）与真实主灯阴影；普通URP额外灯不登记到当前Binding.localLights时，不会自动进入这份自定义local灯循环。背面法线如何处理属于草自身候选，须避免正背面全黑，但不能直接靠无光自发光。

## 草自身普通URP Pass要求

新 Shader 的 Forward、实际启用的 DepthOnly / DepthNormals、ShadowCaster 必须 include 同一草位移和alpha helper。根权重0；用未变形根世界位置和稳定相位；边界按最大摆幅扩展。ShadowCaster法线偏移使用变形后的几何位置；alpha采样/UV裁切/阈值在所有Pass保持一致。DepthNormals只在当前Renderer需要时启用并验证；没有MotionVectors需求时不要为本任务增加TAA/运动模糊。

直接把专用草的普通Depth/Shadow做好，只能证明独立URP路径；**它不解决上述Room固定适配器丢风函数的问题**。未验证Room许可的草不应放进主场/房间遮罩演示里营造“已兼容”的印象。

## 后续共享适配需求（本子任务不实现）

若将来获得共享后端适配授权，需要由Room拥有者统一决定并验证：

1. 新草家族的明确源认证；现有16个reserved renderingLayer bits均已使用，不应随意挪一个他人位。
2. source-aware颜色adapter保留同一草变形/alpha，静态桶和独立路径一致。
3. Truth/标签许可/旧Mask或有效替代路径使用同一变形、alpha、bounds，不能只加颜色Shader。
4. 禁止跨门户边界整块授权；保留现有逐片元许可与所属空间、阴影规则。
5. 对新路径实测准备成本、材质数、重复Pass与未知家族安全拒绝，不能凭源码断言兼容。

这属于明确共享接口工作，不应在本轮草候选内部复制旧Room后端来绕过。独立样场仍可交付形体/风动/贴地/分布/普通受光/成本，G3正式可见性和主场接入列为未通过即可。
